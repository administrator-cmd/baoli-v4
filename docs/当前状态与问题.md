# 当前状态与问题

更新日期：2026-11-03。

## 当前状态

- 后端按实体组织：`app/modules/<业务>/<实体>/{controller,dto,schema,model,crud,service}`。service 不直接操作数据库，SQL 全部在 crud。
- 接口统一返回 `{code, message, data, request_id, success}`；分页统一为 `page` / `page_size`，列表参数在 `app/schema/query/`。
- 审核流程：场景配置 → 发布 → 方案 → 任务 → 材料前置处理 → 字段抽取 → 人工核对 → 计算、规则、报告。
- 模型请求显式设置 `max_tokens`（默认 393216，即 deepseek-v4.1-flash 的 384K 输出上限，配置项 `BAOLI_LLM_MAX_OUTPUT_TOKENS`），避免供应商默认输出上限截断长响应。
- 2026-11-02 实测通过：场景、方案、任务的创建与配置，规则库导入解析，真实 PDF 上传与分类，字段核对保存与确认，任务执行到完成并生成报告，主要前端页面。
- 2026-11-03 源码修改（未运行验证）：规则库第二轮输出输入绑定缺项；计算规则缺输入时禁止按 0 或用相近科目保存正式结果；字段证据增加科目/表头/期间片段和产物页码；字段结果按实际上传文件解析来源，并保存正文实际识别到的期间/口径/主体/单位；报告数据按章节材料范围过滤。
- 当前源码静态修复（未运行验证）：缺项按 `input_id` 逐项核对补取值和真实来源；抽取的上游引用按字段及取值校验并写入字段证据；缺失声明输入不再提前阻断模型补取。
- 当前源码静态整理（未运行验证）：导入缺项只采纳模型声明；结果结构统一先校验；OCR 页面入口校验；配置条目改为普通数据类；核对清单缺失明确报错，不补算历史记录；普通请求与后台工作单元分别管理事务。
- 补取与展示修复（未运行验证）：同一参数的缺项合并；材料补取数字与原文取值一致，换算留在模型计算步骤；规则详情展示补取输入；识别口径绑定本字段已验证的原文片段。核对页隐藏内部 SELF，人工取值与原抽取文本相同时不重复展示。
- 历史验证包含单元测试、真实 HTTP 接口和浏览器页面，不代表上述源码改动已验证。

## 未解决问题

| 问题 | 影响 | 处理方向 |
| --- | --- | --- |
| 业务值随模型诊断重复保存 | 数据库里保留模型响应和输入摘要，含业务值副本 | 对外部署前决定是否脱敏或缩短保留期 |
| 后台失败消息带内部文件位置 | 客户端能看到代码文件名和行号 | 对外部署前统一处理所有输出路径 |
| 启动校验不核对生成列表达式 | 旧库可能仍在用旧的唯一键表达式 | 结构变更后按 `backend/resource/schema.sql` 重建 |
| 复杂规则库第二轮可能超时 | 历史记录显示财报类规则库较慢，近期未复验 | 用真实大规则库重跑确认 |
| PaddleOCR 供应商 500 根因未知 | 只能按失败、续查或重试处理 | 需要供应商侧证据 |
| CSV 崩溃恢复有限 | 进程被强杀、断电、磁盘故障可能留下不完整文件 | 依赖备份和人工恢复 |
| 模型偶发返回非法工具参数 | `LLM_TOOL_ARGUMENTS_INVALID` 会让所在批次字段记为未执行 | 频繁出现时增加把错误回给模型的重试 |

## 验证边界

- 并发幂等、渠道故障续跑、多材料大批次抽取没有在本轮覆盖。
- 下载、流式响应和 204 不套响应信封。
- 静态检查不能代替真实执行；未验证的部分在对应任务里明确说明。
- 历史改造记录和逐轮排查见 git 提交，本文只维护当前结论。
