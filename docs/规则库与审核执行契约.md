# 规则库与审核执行契约

## 设计方向

Excel 的 Sheet 名、数量和布局不决定执行流程。LLM 保留业务原文、来源、材料、字段、规则、计算和报告要求，组成统一规则库。系统执行用户方案中生效的规则，不审查业务合理性，不替业务补造阈值、期间、风险等级或检查阶段。

`execution_contract_version=rule_library_v1`。已移除九阶段 DAG、按节点类型分发的 handler 和确定性业务执行分支。`RULE_EXECUTION` 只用于关联现有数据库中的执行记录与结果，不代表一个业务阶段。数据库执行记录仍以技术容器关联；本轮从建表结构删除旧裁决列，未操作实际数据库。

## 导入与发布

模型候选保留真实单元格来源；内部身份按候选引用生成，原 Excel 业务编号保留。多个材料可共享业务编号；引用单个对象存在歧义时明确暴露，不随意选一个。

导入不提出业务确认问题。停用项保留原文，不检查其算子、参数和依赖。候选 JSON 或来源身份无法加载的单项记录原始返回与失败原因，其余继续导入；响应整体无法读取或程序异常明确报错。

发布不要求固定节点、固定算子、风险等级顺序、报告格式、材料范围或人工复核阶段。缺少业务说明原样保留。编译只组织身份与实际输入输出，生效项的引用错误交给该条执行结果说明，不拒绝整批。

字段定义派生取数项，计算定义派生计算项，报告章节按报告编号组织报告项；这些项同样进入模型循环。已有明确产出规则时，不因该规则停用而另造一条替代规则。原始定义和显式派生身份都保留，用户规则不会因使用 LLM_EXTRACT 或 REPORT_RENDER 被误判为系统规则。

## 任务与规则查询

任务创建时固定方案启用范围、规则库、工具定义与输入版本。`RULE_LIBRARY_QUERY` 只查询这个任务的生效规则，不读后来修改的场景草稿。查询条件可为 kind、rule_keys、rule_codes、query；多个条件取交集，无条件返回全部生效项。查询配置成功不代表审核通过。

不提供旧九阶段执行兼容或自动转换，不改写已有任务快照。旧执行版本进入当前执行器或配置转换入口会明确报错。

## 实际执行

所有生效项进入同一规则循环：取本条输入 → 模型读取规则与真实材料 → 直接抽取、计算或判断 → 按需调用工具 → 保存实际产出和结果。显式字段、规则与计算结果引用决定先后；报告消费结果集合，排在其他生效项之后。缺失依赖或环明确交给当前执行项说明，不阻止无关项。

工具保留真实实现与参数结构，模型自由选择实际可调用的工具，不要求规则预先映射某个算子或业务节点。

- TASK_DATA_READ：读取冻结上传的 Excel 各 Sheet、单元格、公式与缓存值，UTF-8 文本或已生成产物。
- DOCUMENT_PROCESS：明确选择文件处理、OCR、印章或材料类型服务。OCR 所需文件处理产物不存在时明确报错，由模型决定下一次调用。
- 已实现的比较、材料存在性、文件质量、风险等工具仍作为可选函数，不组成预置流程。

工具调用写真实账本；已成功调用恢复时复用已保存结果，外部结果未知时明确说明。模型请求失败、工具失败或产出不能保存时，该条记录具体原因并继续。程序未知异常仍抛出并落失败记录，不吞掉、不模拟成功。

## 结果与人工确认

结果状态为 PASSED、ABNORMAL、COMPUTED、NOT_APPLICABLE、EVIDENCE_INSUFFICIENT、PENDING_REVIEW。纯中间值计算用 COMPUTED，不能当作业务合格。无法完成时说明原因，不能返回假通过。只有业务实际要求人工确认才暂停等待复核。

抽取和计算必须返回声明身份的真实 outputs。服务端核对结果结构、身份和可存储类型；不复核模型业务判断。字段保存 TaskFieldValue 与 TaskFact，计算保存派生 TaskFact；人工确认值不会被模型覆盖，冲突按该条失败记录。

报告正文由模型按生效章节生成并真实保存。目前正文保存与下载支持 Markdown、纯文本、HTML；PDF、Word、Excel 产出没有实现，声明这些格式时不能用 Markdown 冒充。报告同时记录未执行或无法执行的项、范围完整性和风险是否可判定，不把部分结果写成整体通过。

执行批次遍历结束表示调度完成；各条真实状态保留，不能用批次 SUCCEEDED 冒充全部规则通过。

## 本次核对范围

仅静态读取源码并核对 Python 语法、全局名称、相对导入、前端本地导入与显式导出及变更差异。遵照仓库要求，未运行测试、类型检查、构建、服务、数据库或模型接口；尚未做运行验收。

## 旧计算与裁决协议清理

不兼容旧业务裁决记录，不提供数据迁移。导入裁决 DTO、API、目标映射、属性白名单、别名合并、作答暂存、图等待/恢复和前端入口均已删除；场景编辑与方案启停仍通过当前配置接口进行。

删除旧 calculation 编译包、分档校验入口及专用 LLM 计算工具。计算定义不再要求固定引擎、CHECK/VALUE_ONLY 或 JudgementBand；formula 保存计算方法，requirement 保存完整业务要求，business_context 按实际原文标签保留补充信息，来源单元格完整保存。LLM 根据原文执行计算或判断，真实中间值用 COMPUTED 表达。

移除按关键词预判不支持、单位口径预审及旧导入发布接口。任务冻结版本和启用范围仍有效。旧裁决列已从实体、建表 SQL 和启动检查删除，导入不再写入裁决或伪装为裁决的流程元数据；恢复由 checkpoint 保存。本轮没有连接或修改实际数据库。

## 节点、字段与工具目录收尾

场景节点 CRUD、节点选表拒绝接口、孤儿节点面板与死表达式解析器均已删除。来源节点分类、人工复核参数、发布能力缺口确认、未配置检查类别与旧材料状态映射不再进入契约或页面。复核只由当前执行结果的实际要求触发。

工具目录统一在 domain/tool_catalog.py，旧 capabilities.py 及其节点约束、执行分发、参数清单和规则能力预判视图删除。/system/tools 直接返回工具定义；operators/registry.py 保留实际算子实现。任务仍冻结工具实现版本与规则启用范围，这用于真实执行对账，不兼容旧业务流程。

结果读取同步移除旧阶段依赖：跨任务风险列表按当前有效批次的真实风险结果读取；材料识别展示读取当前上传的识别产物。字段取数启用范围来自生效规则输出，不要求 LLM_EXTRACT 算子。前端字段编辑不再提交节点归属。
