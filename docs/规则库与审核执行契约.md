# 规则库与审核执行契约

## 辅助执行原则（2026-10-10）

同一来源业务编号可对应多个材料位（例如同一行的资产负债表、利润表和现金流量表）。导入时按唯一 candidate_ref 生成独立 material_key，业务 source_id 原样保留为 source_ref；字段、规则及执行分支使用具体材料身份定位。导入、材料编辑与发布不要求材料来源编号唯一；仅用共享编号引用单个材料时仍明确报告歧义，不随意选择材料。未导入项目的数量同时显示在解析步骤和写入确认框，写入只包含保留的候选。

普通字段的 RAW_TEXT、DETERMINISTIC 不按 value_type 互斥限制；导入、草稿保存、发布与方案编译共用该契约，模型请求中的 field_contract 同步声明支持。执行端仍按 value_type 对原文做确定性规范化，不自动补齐公司全称或以模型建议值覆盖材料原文；STRUCTURED 只在声明完整 Schema 时按 JSON 对象处理。

导入不生成或受理模型提出的合理性审查、口径确认、阈值确认问题，不提供业务作答入口。原文已有的缺项和待确认说明保留在候选中。历史业务审批记录留存，但不返回为待处理事项，也不阻断写入草稿。结构无法解析的单项保留原始 JSON 与失败原因，其余候选继续导入。

LLM 解析完成即可写入草稿；PENDING 状态仅保留原始说明，不要求确认能力缺口后再发布。只执行生效规则；停用来源保留原文，停用候选保留完整原始配置，不解析或编译其算子、参数及依赖。仅核对生效配置的 JSON 结构、真实来源、引用身份、节点归属及执行顺序，不评审规则的业务正确性，不补默认口径。

语义规则即使没有工具也进入 LLM 执行。模型能完成的抽取、计算和判断直接执行；需要额外能力时通过 tool_calls 选择该节点已有、可调用且无副作用的工具。工具只接收事实身份，系统从本次快照读取真实输入，支持选择输入子集。工具失败保留真实错误。无法完成的规则记录 EVIDENCE_INSUFFICIENT 与原因后继续，只有业务明确要求人工确认才等待复核。

风险模型直接读取本次真实上游结果；不强制调用风险工具，也不因缺少风险条件、等级或处理建议在导入阶段拒收。计算缺少判断标准、单位或币种不阻断发布，具体能否完成由模型按原文说明；当前专用计算节点没有独立计算工具，不伪造工具补救。

报告配置要求按风险等级排序但未提供 risk_level_order 时，不阻断场景发布，保留原始排序要求与空顺序。实际报告排序仍明确返回 REPORT_LEVEL_ORDER_REQUIRED，不猜测等级高低或静默改用其它排序。场景详情按当前配置重新计算发布原因，避免历史 sync_error 锁住发布按钮。

工具策略版本为 2，新发布版本冻结该策略；旧发布快照、既有任务不自动迁移。此次仅静态核对，未运行测试、构建、服务、数据库或模型接口。

## 导入中止与删除（2026-10-10）

规则转换先读取输入并结束事务，等待模型期间不持有作业行锁。返回后按作业、后台命令顺序加锁，核对命令仍为 RUNNING 且草稿修订未变化，再替换候选或记录转换失败。中止后旧线程不能写回草稿，也不能覆盖 INTERRUPTED 状态；正在转换的作业需先中止再物理删除。前端删除期间显示加载状态，失败原因持续显示。

每次转换使用独立的检查点 thread_id（作业号与转换批次组合），裁决恢复使用同一身份，避免中止后重试受旧线程干扰。无需改表；本改动前已进入裁决等待的旧作业需重新解析，旧检查点不自动迁移。

## 场景驱动风险与报告（2026-10-09）

风险等级接受场景原文，不再使用固定等级枚举。risk_condition 保存完整业务条件；节点和 Agent 共用 RISK_TRIGGER，由 LLM 读取当前有效的来源检查/计算结果判断，来源中间值不被自动当成合格。风险等级和处理建议保持配置值，模型不得重定。

报告章节的 content_instruction 实际交给共用 REPORT_RENDER 生成正文。程序先按材料范围筛选，再执行 result_sort；risk_level_order 保存从高到低的显式等级顺序，缺失或实际等级未包含时明确报错，不按等级名称推测。模型可按章节要求概述或选择明细，已选明细保持程序排序，不能引用未提供的来源。删除固定九节正文，业务章节为主体，系统保留执行完整性与风险可判定性摘要。

字段 DECIMAL 表示普通数值，AMOUNT 表示金额；普通数值不再被强制声明币种，金额继续保留单位与币种口径。配置、候选、编辑、发布、方案复制、抽取、事实与 CSV 读取链路同步支持。配置仍存已有 config_json，等级顺序不增加实际数据库列，本轮无需重建数据库。风险与报告能力版本、工具目录版本已递增；旧冻结任务不会静默按新工具契约执行。

本轮只做静态源码核对，未运行测试、构建、服务、数据库或真实模型调用；PDF/Word/Excel 文件生成仍未实现。

方案章节编辑同步保存风险等级顺序。报告模型同时收到任务的缺失结果、未完成字段、待复核项及风险可判定状态，不得根据部分结果声称整体通过或无风险。来源引用校验只验证身份与顺序，不保证模型正文的业务语义完全正确。

既有金额字段如果标记为 DECIMAL，需在场景配置中明确改为 AMOUNT；系统不会根据字段名称或原文猜测并迁移类型。旧冻结任务的工具契约与当前版本不兼容，不能直接沿用；应使用核对后的新配置创建任务。

## 模型传输（2026-10-09）

规则库完整解析与停用来源增量解析接收到完整模型正文后，在 JSON 解析和候选校验之前原样保存到 data/llm_responses/<operation_no>/response_<唯一编号>.json，并独立提交 background_operation.raw_response_path 文件索引；解析或业务校验失败仍保留。不保存请求、密钥或推理内容，不将无效返回当作候选。操作查询及导入详情的 latest_operation 返回相对路径，字段结构错误的具体路径和原因写入 failure_message。断流及 length 截断仍明确失败，不产生完整返回文件；保存文件或索引失败也向外报错。

统一模型网关使用 Chat Completions SSE 流式传输，后台任务仍在完整结果通过业务校验后保存候选或审核结果；前端不展示或保存生成中的半份配置。正文、推理内容及工具参数分别按流式片段组装，工具身份与参数原始字符串保留。请求仍发送所选工作表的完整内容，不按工作表拆分或截断。

接收必须包含 `[DONE]` 和结束原因；流内错误、无效结构、缺失结束标记及 length 截断明确失败。JSON 请求还要求 stop 正常结束。既有临时 HTTP、网络和超时重试保留，每次重新组装响应；不对不完整流做业务补全或退回非流式。日志记录首个数据块和完整接收耗时，不记录模型正文或密钥。本轮仅静态修改，未调用真实接口或运行测试，不能宣称远程 504 已消除。

## 场景规则库与 JSON

节点执行入口与工具由各场景共用；当前场景配置决定字段、输入来源、计算方法、判断标准及规则归属。计算编译器接收字段目录与计算配置，不读取固定 Excel 表名或按场景编号选择算法。期间与报表口径仅在规则实际涉及时用于事实定位；缺省由系统内部归一为 NOT_APPLICABLE，不要求业务字段或计算候选显式填写。现有枚举及数值结果结构仍按当前执行契约核对。

字段抽取归属从字段或独立抽取规则读取，不再使用历史工作表角色绑定决定节点；缺少显式归属时沿用现有唯一同类节点解析，多实例无明确归属时发布报错。导入写入按真实工作表身份和参数/判定区间的来源引用核对选入及排除范围，不按“计算参数表／判定表”角色整体阻断。模型可见的候选说明与规则库提示以实际业务配置为准，汇总、分组、常量比较使用已提供真实输入，不因方法名称声明能力缺口。

LLM_VALIDATE 不在草稿编辑或发布时限制输入数量、类型、单位或币种，正文检索模式同样向模型提供全部声明输入。工具真正调用时仍须满足其接口结构，调用失败按实际错误回传。

每个场景有自己的 Excel 规则库，管理员选择参与解析的工作表，不要求固定表名、固定表头、统一列模板或一表一种用途。LLM 在同一次请求中读取选入表的完整单元格、真实地址、合并区域和当前可用节点、算子目录，生成材料、动态字段、抽取要求、规则、计算及报告章节 JSON。界面预览截取不影响模型读取原文。

系统定义可执行配置协议，业务名称、字段集合、公式、条件与阈值来自本次 Excel。LLM 可以按真实规则库设计字段，也可声明结构化抽取及其 JSON Schema；不生成任意 Python 或执行代码。节点能力单独保存在 node_profile.json，场景 schema 只记录版本身份，业务定义保存在 config_json。固定模板配置、模板下载接口、标准列匹配和确定性模板转换路径已删除。新场景默认身份为 scenario_json；历史身份仍可读取，空 sheet_overrides 只用于兼容既有记录，非空模板覆盖明确报错，不静默忽略。

明确写出的口径直接识别为 CLEAR，只有缺失、矛盾或引用歧义提出可裁决的问题。后端核对真实单元格来源、引用身份及节点归属，原文由真实 Excel 回填；每个非空行有候选、合并对象、停用原文或明确排除理由。模型遗漏、伪造来源、响应格式无效或请求失败都显式报错，不使用程序解析兜底。

业务编号存在时保留，没有时 source_id 保持空；内部候选引用用于配置身份，不冒充业务编号。公式参数可按内部引用定位没有业务编号的字段，写草稿时转成稳定字段键。非财报业务的字段与计算结果可以省略期间或报表口径，系统内部归一为 NOT_APPLICABLE，不强行套用本期或合并口径。

scenario_draft.config_json 保存节点、工作表来源、材料、字段、规则、计算、报告、停用行以及原始模型提案。audit_plan.config_json 保存方案自己的业务配置与只读执行上下文，原始提案随发布与复制保留。编辑器复用属性视图访问 JSON，旧 scenario_draft_*、plan_* 配置明细表不再建表、查询或写入。已发布版本的关系投影仍用于任务身份与外键关联。

新导入的来源表清单保留真实 sheet_key、sheet_name 和上传顺序，随草稿、发布版本、版本还原及方案重新编译传递。动态表的 node_code 为 null，表示业务配置分别指定节点；历史模板清单仍保留角色与表级绑定。旧清单未记录真实表名时如实显示未记录，不从内部标识猜名称。

## 审核任务与 CSV

抽取原文、规范值、计算派生值及规则结果写入任务 CSV。字段校验、计算、Agent 冻结输入、报告与任务结果视图按当前上传或执行身份选择记录，再从 CSV 恢复业务值；同一批中的下游计算也重新读取 CSV。CSV 不是单纯导出文件。

CSV 使用标准库处理引号、逗号和换行，UTF-8 BOM 便于 Excel 阅读。十进制字符串还原为 Decimal，日期还原为 date；结构化结果保留 JSON。CSV 行包含材料、字段或计算身份、类型、单位、币种、期间、当前状态、修订号、原文、取值及完整关联数据。

抽取节点重试时，字段失效范围只包含受影响节点在本任务中选中且启用的抽取规则输出，并核对冻结字段范围；完整节点契约中保留的停用定义不参与失效。结构化 JSON 的有限小数在事实快照中保持 number 类型，金额继续使用 Decimal 的十进制编码；非有限数明确报错。

数据库仍保留任务状态、证据、复核、事实和规则结果索引及其投影，不在此轮移除这些证据关联。执行值从 CSV 读取，文件缺失、哈希变化或索引记录缺失直接报错，不退回数据库数值。材料替换、人工纠错、复核和下游失效同步 CSV 的版本与当前状态。

文件在同一任务、事务层级内复用一个未提交路径，原子替换；嵌套事务使用独立路径，避免回滚后父事务的指针指向已被覆盖的内容。跨根事务创建新文件，audit_task.intermediate_csv_json 保存文件位置、哈希与记录数量。保存点提交和回滚不清理外层路径映射，根事务结束才清理会话映射。回滚不会覆盖已提交文件。历史事务文件及失败事务遗留文件保留，不自动清理。任务页面提供当前中间 CSV 下载。

## 执行能力

新规则库的计算候选明确声明 execution_engine=LLM。formula 保存完整的业务计算方法，可为自然语言或算式，不经过四则表达式解析；calculation_type 使用业务描述，不限定四种财报指标。CHECK 使用 judgement_instruction 保存完整判断标准，也可保留简单 bands；VALUE_ONLY 不配置判断标准。参数引用、来源定位、节点归属与依赖循环仍由程序检查。

计算节点从本次任务 CSV 读取有效字段值及上游结果，支持数值、日期、文本、布尔和结构化记录输入，通过中文说明的 @tool("LLM_CALCULATE") 调用已配置模型直接计算与判断。模型返回数值、状态、输入参数引用、运算摘要和判断理由，写回派生事实及 CSV 规则结果；同批下游计算重新读取 CSV。程序只核对 JSON、结果身份、引用和数值类型，不重新计算业务结果或程序判定区间。当前计算结果仍为单个数值，其他业务结论由智能校验输出状态和说明；没有新增任意代码执行功能。模型调用、响应或引用错误显式失败，不回退到公式引擎。

新字段业务校验使用 LLM_VALIDATE。evidence_source=FIELD_FACTS 时，LLM 直接读取 CSV 字段值及状态，内部校验可声明多个输入，条件、汇总、固定常量比较和文字判断不要求专用算子。字段缺值是否影响当前分支由模型依据业务要求判断，确定结论仍须引用本次输入。确需检索原文时使用 RETRIEVAL 并保留真实引文核对。外部查询没有数据来源的能力仍不补造；完整记录集合需要真实抽取，不能把少量样本当作全量。LLM_VALIDATE 能力版本为 2。

场景及方案 JSON、发布冻结、重新编译、增量解析预览、动态导出与回导保留执行方式、业务方法和判断标准。计算配置必须明确声明 execution_engine=LLM；PROGRAM 或未声明执行方式的历史计算在发布、重新编译及执行入口明确报 CALC_PROGRAM_RETIRED，需由 LLM 重新解析规则库，不静默改变历史语义。页面提示旧计算需重新解析，已有任务结果不改写。未声明 evidence_source 的旧智能校验仍沿用正文检索。本次清理未改数据库结构，未运行模型或真实任务验收。

工具实现函数使用 LangChain 标准 `@tool("内部标识")`，中文文档字符串作为工具描述，签名推导执行参数结构；算子注册表直接保存工具对象，并从对象名称取得内部标识。算子、工具服务及工具间调用均通过 `.invoke()` 执行，不再使用自定义标注装饰器。材料工具的运行期上下文用 `InjectedToolArg` 标记，由系统注入，不进入模型可见参数结构。模型侧仍使用发布时冻结的业务参数约定：只提供身份引用，真实字段取值由系统解析后交给工具；通过 `convert_to_openai_tool` 将冻结定义转换为标准 `name`、`description`、`parameters` 请求，中文用途与输入说明来自工具目录。

流程节点仍由管理员配置，LLM 将业务配置归到实际启用节点，不自动生成 LangGraph 节点。发布校验节点引用、依赖与算子契约；工作表可以承载多个节点的规则，计算可以分布在多个计算节点，跨节点输入依赖必须明确配置。普通节点目前仍逐个等待确认；现有发布版本、任务配置冻结及流程检查点机制继续保留。数据库当前按开发验证阶段维护最终 schema.sql，结构变更由用户从空库重建；不维护备份或迁移脚本，checkpoint 只创建运行所需三张表，不创建迁移记录表或调用 saver.setup()。

普通规则读取字段时，启用抽取规则所在的启用节点必须是消费者自身或其直接/间接上游，不以页面顺序代替 DAG 依赖；没有启用抽取来源时不自动重新开启抽取。场景发布及方案保存复用此检查。字段显式 node_code 作为 config_json 的扩展属性保存，场景字段编辑器展示真实归属并允许修改；已有启用独立抽取规则时其节点决定实际归属，字段提交不同节点明确报冲突。删除节点核对普通规则、字段显式归属、计算（含停用定义）、历史工作表绑定及下游依赖，不遗留悬空引用。

规则节点修改后，从当前场景真实节点读取对应类型，候选展示、保存和写入草稿一致；不沿用原候选类型，也不根据节点名称猜测类型。检查等级按业务原文填写，通用 DECIMAL 作答只核对有限数，不统一强制非负；具体算子保留自己的参数约束。

计算 CONSTANT 参数可提供数值、日期或文本，按完整业务方法交给 LLM，不再按旧算术引擎统一强制转成 Decimal。计算输出仍是单个数值。CHECK 已算出数值但无法确定判断标准时可保留数值并返回 EVIDENCE_INSUFFICIENT；确定判断须有判断说明。计算结果的风险等级、建议同时供报告读取，不再只留在模型响应内部。

各模型响应 Schema 使用本次真实字段、参数、来源或下标范围；没有可引用项时声明空集合，不生成非法空 enum。程序仍核对实际响应身份、引用、类型和状态，错误明确失败，不静默降级或伪造成功。仅完成源码及静态核对，未执行本轮真实模型或运行验收；不涉及数据库结构调整。

## 场景删除契约（2026-10-09）

删除场景实际移除身份记录与 JSON 草稿，成功返回 204，不返回已不存在的场景详情，不提供恢复接口。管理员页面删除后回到场景列表，列表不提供“已删除”筛选。版本分配和初始化脚本不得根据历史版本重新创建已删除场景。

已有方案、任务、导入历史及已发布执行快照独立保留；本操作不级联删除它们。新方案仍要求来源场景存在，已有方案继续读取自己的配置及绑定版本。旧场景删除标记列仅作为存储兼容保留，新删除不使用该列。仅静态核对，未运行本轮删除验证或实际删除数据。
