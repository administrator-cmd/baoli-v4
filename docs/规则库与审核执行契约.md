# 规则库与审核执行契约

## Excel 解析

全部非空 Sheet 交给 LLM，不要求固定模板、表头或工作表绑定。解析分两轮：

1. 第一轮读取 Excel，生成 materials、fields、rules、calculations、report_sections 五类目录，只含内部引用、原名称、编号、状态和来源行。
2. 第二轮接收第一轮目录、同一 Excel 原文和格式说明，生成完整执行配置，修正漏项和引用；逐项核对公式/条件与实际输入绑定，输出 `binding_gaps`（所属对象、缺少的输入、原因和原文要求），空数组表示逐项核对后没有缺项。

第二轮必须区分“公式文字完整”和“输入绑定完整”：同一字段不能同时充当两个不同期间、口径或含义的参数；原文明确存在但尚未建立字段/计算/常量绑定的输入，可以按原文补字段或写入缺项，不能编造科目、期间或常量。缺输入不改变原文的启用、待确认或暂停状态。

第一轮响应先按 `WorkbookInventory` 校验，不合法不保存。第二轮保存前检查引用唯一、非空且可解析，并检查同名同材料同期间/口径/主体的字段身份不重复，不合法返回 `LLM_CONTRACT_INVALID`，并列出对象和具体引用。

第二轮结果保存在 `import_job.proposals_json`。业务对象的 `origin` 保存真实 Sheet 名、来源行和原始单元格；模型只返回位置，程序从工作簿补上原文。`origin` 用于页面溯源，不发给模型。

`candidate_ref` 只在导入对象之间使用，写入草稿时换成内部键。`rule_key` 是规则内部身份；`rule_code`、`source_id`、`report_code` 保留原业务编号，没有编号就留空。同名但材料、期间或范围不同的对象分别保存。

## 配置与发布

配置状态：

- `CLEAR`：启用；
- `PENDING`：待确认，暂不执行；
- `DISABLED`：暂停。

待确认项可以保存和发布，不阻止其他规则。管理员启用后才执行。字段不抽取、计算不运行、报告章节不生成。

场景草稿和方案配置保存在 `config_json`，编辑条目是普通数据类，不映射独立明细表。发布时编译配置，发布成功后删除草稿，两步在同一事务提交。读取配置时，有草稿读草稿，否则读已发布版本。

新建方案必须带 `idempotency_key`。同键同内容重发返回原方案；同键不同内容返回冲突；不同键相同内容仍创建新方案。方案、配置、编译结果和操作日志同一次提交。

## 执行

执行契约版本为 `rule_library_v1`。`RULE_EXECUTION` 只是关联执行批次和结果的容器，不是可编排的业务节点。

每条规则带 `execution_mode`，取值为：

`MATERIAL_CHECK`、`VALUE_COMPARE`、`CROSS_SCOPE_COMPARE`、`AGGREGATE`、`DERIVE_RISK`、`EXTRACT`、`CALCULATE`、`REPORT`。

执行方式决定给模型什么上下文：

- 材料检查只给材料和产物；
- 字段比较、跨范围比较只给声明的输入；
- 组合汇总由程序按来源规则状态计算，不调用模型；
- 风险推导只给来源规则结果；
- 字段抽取、计算按声明输入取数；
- 报告按章节数据生成。

执行方式缺失或 `UNKNOWN` 时，发布返回 `RULE_EXECUTION_MODE_MISSING`，不默认按普通核查执行。

### 任务图

固定八个节点：

`load_task → execute_current_node → prepare_materials → load_evaluation → execute_rules → finalize_node_execution → advance_workflow → save_node_result`

图没有回边，步数不随规则数量或模型轮次增长。执行计划按规则声明的依赖生成一次，同层内按执行方式排序（抽取、计算、材料检查、比较、汇总、风险、报告）。每条规则的产出和结论在同一个保存点提交；格式、证据或产出错误只把该条记为 BLOCKED，后续规则继续。

### 材料前置处理

审核材料只接收 PDF、PNG、JPEG、TIFF。建立批次后、加载规则前运行 `prepare_materials`：

- `MATERIAL_CLASSIFY`（8018）完成后，`DOCUMENT_PARSE`（8010 去章）和 `SEAL`（8003 印章）并行；
- 去章完成立即进入 OCR（PaddleOCR），不等印章；
- 8018、8010、8003 各自逐份处理，上一份离站后继续下一份；OCR 作业独立提交、独立续查。

每份材料的四项都成功才进入业务规则。某一步失败只跳过依赖该步的后续处理，其他分支继续保存真实结果；全部步骤收尾后汇总错误并阻断审核。已完成产物复用，不自动重提未知作业。

材料处理状态支持只读查询和单项重试。`PROCESSING` / `SUBMITTING` 等结果未知状态，必须由用户确认（`resubmit_unknown=true`）后才重新提交。

### 工具

| 工具 | 作用 |
| --- | --- |
| `TASK_DATA_READ` | 读取 OCR 正文，或读取 SEAL、MATERIAL_CLASSIFY 产物 |
| `RULE_LIBRARY_QUERY` | 返回本任务固定规则的目录；按编号查询时返回完整配置 |

工具按当前目录提供，不保存逐规则的授权表。`DOCUMENT_PROCESS` 不提供给模型，前置程序直接调用。

模型可用工具只保留需要真实文件或外部能力的部分：读取材料产物（`TASK_DATA_READ`）、查询冻结规则库（`RULE_LIBRARY_QUERY`）、文件大小/格式/哈希等质量检查，以及结构化风险推导（`RISK_TRIGGER`）。

字段是否一致、日期先后、数值大小与加总、字段非空、条款是否存在、材料位是否齐全，由模型直接依据规则原文、字段事实、材料清单与上传状态判断，不再提供比较类工具。这类结论的证据可以引用字段事实（优先 `fact_id`，或 `field_key` 与完整口径）或上游 `rule_result_id`，不要求工具调用记录；材料是否齐全的依据写入 `basis`。

单条和批量字段抽取在调用模型前按声明预读真实产物，直接注入上下文，并移除本次 `TASK_DATA_READ`，避免重复读取。其他需要动态读取的规则仍可使用该工具。工具实现或环境错误直接上抛；模型参数和业务状态错误交回模型修正。

### 批量抽取

同一材料、同一产物来源上连续的多条单字段无输入抽取合并成一次模型调用。模型请求显式携带 `max_tokens`（默认 393216，即模型输出上限），避免供应商默认输出上限把长响应截断。模型看到本批短编号（批次前缀-序号），保存前换回内部字段键。无法识别的编号只让对应字段记为未执行，不影响同批其他字段。

合并只发生在相邻、互不依赖且没有输入绑定缺项的抽取项之间。每条字段仍各自保存、各自成败；批次整体失败时保存批次级原因，不自动追加逐条模型调用。

### 计算输入

计算规则调用模型前列出每个参数的来源、状态和取值；字段输入未形成有效事实、上游计算结果未形成 `COMPUTED`，或解析阶段已记录 `input_gaps` 时，模型不能把这些输入当作 0，也不能用相近科目、其他期间或其他口径替代。

必要输入缺失时不在模型调用前直接阻断。上下文与保存校验共用 `missing_rule_inputs` 生成缺项清单，每项带本条评估内的 `input_id`。模型按项返回 `input_resolutions`（身份、取值、原始写法、单条证据）；材料原始写法必须出现在已核对的引文中，事实来源必须有有效取值且与补取值一致。已绑定字段只能从其声明材料补取，未绑定输入仍限本条允许的材料范围。

正式结论必须覆盖全部必要缺项，任意一条真实引文或上游结论不再解除全部缺项；未补齐时返回 `EVIDENCE_INSUFFICIENT`。零值和 false 是有效值，不默认补零。该校验也用于比较规则的缺失字段及非计算规则的绑定缺项；不改变规则业务判断。科目含义、期间和单位换算仍由模型依据原文判断，程序只校验身份、取值和来源契约。

### 字段来源

成功抽取字段需要本字段的非空真实引文；人工核对值沿用已有结论。字段事实或上游结果替代引文时，必须对应同一输出字段及相同有效取值，不能仅凭任意 `rule_result_id` 豁免。上游引用明确填写 `output_code`，保存时将对应字段版本写入新字段的证据链，不继承整条上游规则的其他材料。

### 轮次与诊断

轮次按单条规则的实际模型调用计数，处理下一条时从零开始。`llm_tool_max_rounds` 默认 12，设为 0 关闭限制。轮次耗尽保存 `LLM_TOOL_LOOP_LIMIT`，继续处理其他规则。

结论格式、引用身份或声明产出校验失败时，完整模型响应写入 `data/tasks/<task_no>/diagnostics/rule_verdict_errors/`，路径记入 `verdict_errors`；成功响应不落盘。

## 字段核对

抽取完成后任务停在字段核对等待点。执行计划分成抽取段和核对后段：抽取段是 `EXTRACT` 规则及其依赖闭包，其余规则属于核对后段。没有抽取规则时不存在核对步骤。

抽取规则依赖抽取以外的规则时，规划阶段返回 `AUDIT_FIELD_REVIEW_DEPENDENCY_CONFLICT`，列出具体规则，不自动跳过核对。

等待期间：

- `POST /audit-tasks/{task_no}/field-review/save`：追加人工字段版本和人工记录，不失效批次、不重跑规则；每次保存递增输入修订。
- `POST /audit-tasks/{task_no}/field-review/confirm`：保存剩余修改，写入 `field_review_confirmation`（绑定批次、输入修订和字段版本摘要），然后在同一批次执行核对后段。
- 仍缺值时页面列出真实缺项，用户确认后才继续；不补值，不默认通过。
- 等待状态下 `/execute` 和字段纠错入口拒绝执行。

字段或材料版本变化后，旧确认不再匹配，需要重新核对。抽取段结束后不再重跑抽取规则；人工补填值不会被模型覆盖。

## 取值与数据库

每个任务按业务列保存取值：

- `values.csv`：字段候选、有效事实、计算结果；
- `rule_results.csv`：规则结论；
- `rule_items.csv`：判断依据、实际产出、缺失事项；
- `value_details.csv`：结构化属性的子节点。

结论状态、原因和风险等级只存数据库，CSV 不保留副本。格式版本 6 只登记 `current` 一组四表。写入按记录身份合并后原子替换；四张表落盘后才更新清单，清单与业务索引同一次提交。

| 数据 | 位置 |
| --- | --- |
| 导入配置、场景草稿、方案、发布版本、任务配置 | 数据库 JSON |
| 字段原文值和规范值 | CSV（TaskFieldValue） |
| 字段事实、计算结果、单位、币种 | CSV（TaskFact） |
| 规则产出和业务结论 | CSV（RuleResult） |
| 字段、事实、规则结果的身份、版本、状态 | 数据库索引 |
| 规则结论文本、风险等级、执行诊断 | 数据库 `rule_result` |
| 证据原文和文件关系 | 随业务值保存在 CSV，不单独建表 |
| 报告正文、状态、范围说明 | 数据库 `audit_report` |

Decimal 和日期用带类型标记的封套保留精度；结构化值以 JSON 保存。业务对象恰好长成标量封套时，改用键值对列表转义。

模型从正文实际识别到的期间、报表口径、主体范围和单位，作为 `values.csv` 主记录的补充属性保存（`actual_period_scope`、`actual_statement_scope`、`actual_entity_scope`、`actual_unit`），不改变四张表的列结构；配置声明的口径仍保存在“期间/报表口径/主体范围/单位”列。页面优先展示实际识别值，未识别时明确写“未识别”，不与配置值混用。

CSV 缺文件或索引对应的记录缺失时明确报错。文件系统与数据库没有分布式事务，进程被强制终止或断电时仍需靠备份和人工恢复。

## 结果与报告

结果状态：`PASSED`、`ABNORMAL`、`COMPUTED`、`NOT_APPLICABLE`、`EVIDENCE_INSUFFICIENT`。抽取和计算必须返回声明的输出；程序只核对结构和身份，不重新裁定业务结论。

用户结果区展示状态和业务原因。模型 `message` 用短语或短句，不复述执行步骤、工具名称或内部编号；取值和依据放 `basis`，缺项放 `missing_items`。本阶段不展示或生成处理建议，`next_action` 保留字符串字段但填写空字符串；报告也不传播历史操作建议。规则原文明示的业务处置要求仍属于配置内容，管理页明确标为“规则配置的处置要求”。材料未载明和无法读取必须区分。执行完成不等于审核通过。

页面不根据错误码拼接查日志、修改场景配置等通用操作建议，也不引导用户使用未启用的人工审核、独立重算或报告生成入口。错误原因、缺项、历史结果失效和诊断信息如实保留；上传、字段核对、查询、续跑、重试等动作仅由所属页面按实际状态提供。字段纠错保存不等于已重新执行审核，空的 `recomputed_rules` 不能被解释为没有受影响规则。

材料要求名称与实际来源文件分开表达。事实上下文的 `source_files` 按该事实真实证据对应的上传版本解析；预读及工具产物的 `filename` 来自实际读取的上传文件。模型描述来源时使用这些真实文件名，不能把 `material_name` 或材料清单的 `name` 当作文件名。判断依据区独立列出本条引用文件；历史说明中的配置材料名称显式标为“材料要求”，不改写已保存结论，不根据名称或数值猜测逐行文件归属。

执行详情只展示逐条执行状态、模型轮次和技术问题；业务结论在规则结果中查看，不在执行记录里重复。

证据引用核对实际工具结果、字段事实或上游规则结果。引用工具产物但没有引文时，只记录来源，内容核对为 `NOT_CHECKABLE`。引文核对与业务结论相互独立。

引用表格时，`quote_text` 是目标值所在单元格的真实文本；`quote_label`、`quote_header`、`quote_period` 分别保存科目/行标签、列/期间表头和期间原文，每个片段都按真实正文独立校验；不能把不相邻单元格拼成一条引文。`artifact_page` 只表示 OCR 产物内页码，不冒充原 PDF 页码。展示来源文件时按证据关联的上传版本解析，不用材料位当前文件名覆盖历史结果来源。

报告按章节读取字段、计算结果和规则结论，缺少数据要在章节里说明，不编造内容。章节声明了材料范围时，`report_data` 只提供该范围内的字段事实和生产规则的结论；被范围排除的数据明确记为缺项，不再作为正文依据。报告正文目前支持 Markdown、纯文本和 HTML，未生成其他格式时明确标记。

## 恢复与继续执行

可继续的批次：`BLOCKED`、`WAITING_FIELD_REVIEW`、结果已提交但图未推进的 `SUCCEEDED`，以及允许重算的 `FAILED`。

`FAILED` 是否放行，看已提交的规则结果是否仍然可信：

- 服务重启、模型渠道故障、程序异常、存储暂时不可达：可以沿用原批次；
- 缺材料、缺执行方式、批次对不上等输入或配置问题：先处理原因。

继续执行复用当前批次，只重跑未完成项及全部下游；已完成的规则保留。报告依赖全部非报告项，会自动加入重跑。保留、补跑、受依赖影响的数量由服务端计算，页面只展示。

“全部重新执行”是独立操作，用户确认后另建批次重跑全部生效规则，旧批次失效但保留原因、结果和证据。

模型渠道故障（网络失败、超时、鉴权失败、配置缺失、流未正常结束）和结果未知（`LLM_RESULT_UNKNOWN`）会停止后续模型请求：当前规则按真实错误记为未完成，已形成的结果照常提交，批次以 `AUDIT_LLM_CHANNEL_UNAVAILABLE` 结束。结果未知时不自动重新 POST，继续执行前页面提示可能再次产生费用。

被重试、纠错或材料换版取代的执行记录标为 `INVALIDATED`，原状态和原因保存在 `result_json`；列表同时显示原结局和“已失效”。

## 限制

- 审核图没有持久化 checkpoint，只保留当次运行的内存状态。
- 除字段核对，没有其他人工等待点；通用审批流程不启用。
- 没有列表 CSV、中间值或原材料的下载、预览入口，只有报告下载。
- 数据库结构由 Alembic 管理，`schema.sql` 与当前 head 一致；应用启动只做只读校验，不自动建表或迁移。


## 结构校验与执行记录

导入程序只核对模型输出结构和显式引用，不根据参数名猜期间、科目或报表口径，不因多个参数复用同一事实自动制造缺项。缺项仅来自模型明确声明。

单条和批量结论先按同源 JSON Schema 校验结构，再核对产出身份、状态、真实引用和引文。批量按字段校验，单字段错误不拒绝整批。OCR 产物在保存、读取入口核对页面结构；空白页保留，坏页面明确报错，不跳过后生成空正文。

缺失输入按明确的参数编码合并，同一参数的字段缺值和声明缺项只生成一个补取身份，缺项原因保留。材料补取的数值保持原文数值与原文单位，允许数字格式差异；单位换算由模型在计算步骤完成并说明依据。规则详情展示补取采用值、原文值和来源。

字段实际识别的期间、报表口径、主体和单位必须对应本字段引用中的原文片段，不能只凭该文本出现在整篇材料中通过校验。程序核对引用归属和原文一致性，表格行列及业务口径仍由模型判断。
