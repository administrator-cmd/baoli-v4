# 规则库与审核执行契约

更新：2026-09-16。性质：历史 Profile 输入与执行契约；部分条款待重审（legacy only）。

> 2026-09-16 评审提示：本文七 Sheet 格式描述针对既有 Profile，不应被扩大为所有场景的输入限制。用户提供的九 Sheet 规则库及 09 关系表、LLM 主导配置与审核、运行期工具调用的设计见 [场景化审核Agent需求与设计评审稿.md](场景化审核Agent需求与设计评审稿.md)。本文禁止 LLM 表头匹配、仅检查行维护风险来源、单字段/同材料算式、以及冻结全部运行路由等旧口径与新需求有差异，当前只评审，不据此改写历史任务或开始编码。

本文定义 Excel 规则库如何被确定性读取、发布和执行，以及印章主体检索的边界。它不记录本机样本路径和临时实现进度；当前差距见 [当前状态与问题台账.md](当前状态与问题台账.md)。

## 1. 格式版本与兼容

规则库 profile 是外部格式协议，不是业务规则。`contract_review_v1`、`v2`、`v3` 已经形成历史解释；旧场景、旧任务和旧文件继续按其原 profile 读取，不能因当前设计变化被重新解释。

节点版后续修订必须新建 profile 版本，不能直接改变 `contract_review_v3` 的列语义。新版本修正两项契约：

1. `材料名称` 与 `材料类型` 分列；
2. canonical 列名和 `aliases` 都参与确定性表头匹配。

系统默认使用哪个 profile 由后端配置决定；上传文件能通过唯一表头签名识别时使用匹配版本，无法唯一识别时明确报错，不猜版本。

## 2. 三类限制必须分开

| 限制 | 含义 | 当前代码默认值（未获用户批准） |
| --- | --- | --- |
| 规则库上传上限 | 本系统接收 `.xlsx/.xlsm` 配置文件的传输限制 | `max_rulebook_bytes = 30 MiB`，可配置 |
| 业务材料上传上限 | 本系统接收合同、协议等真实材料的传输限制 | `max_document_bytes = 128 MiB`，可配置 |
| 规则库预览范围 | 页面或 LLM 快照的显示/传输范围 | 前 200 行、前 40 列、单元格前 500 字符 |

规则库和业务材料是不同输入，不能共用一个大小常量。两个上传值只校验为正数，不设置写死的代码上界；反向代理、8018、8010、OCR 等系统可能另有体量限制，必须依据真实部署和外部契约分别说明。

前端从后端能力接口读取上传限制并显示同一数值，不再复制常量。模板说明页可以动态显示规则库上传限制，但该说明不是业务审核规则。`02_文件处理` 中的“文件大小”标准是用户配置的业务检查，与上传入口限制完全不同。

预览范围不限制完整解析。源文件中的全部业务行必须逐行形成候选、明确排除或问题记录；不能只处理前 200 行却声称整本规则库已转换。

单位必须写清：配置值按字节保存；界面若显示 MiB，则 `1 MiB = 1,048,576` 字节；若业务规则使用 MB，则 `1 MB = 1,000,000` 字节。不得把二者混写。

## 3. 修订节点格式

对既有 `contract_review_v3/v4` Profile，固定七个业务 Sheet，每个 Sheet 一张连续表，第一行为表头。行数是业务数据，不设样例数量常量；这不是所有场景的工作簿结构要求。

| Sheet | 列名 |
| --- | --- |
| `01_材料检查` | 材料编号、材料名称、材料类型、是否必传、配置状态、备注 |
| `02_文件处理` | 规则编号、检查名称、适用材料、检查项目、合格要求、检查口径、标准值、单位、检查等级、关联风险、配置状态、备注 |
| `03_字段抽取` | 字段编号、所属材料、字段名称、数据类型、单位、币种、是否必抽、产物来源（可选）、提取要求、配置状态、备注 |
| `04_文件内部校验` | 规则编号、检查名称、适用材料、检查字段、合格要求、对照内容、允许差值、差值单位、检查等级、关联风险、配置状态、备注 |
| `05_文件交叉校验` | 规则编号、检查名称、材料、检查字段、合格要求、对照材料、对照内容、允许差值、差值单位、检查等级、关联风险、配置状态、备注 |
| `06_风险评定` | 风险编号、风险名称、风险等级、成立条件、风险说明、人工核查建议、配置状态、备注 |
| `07_报告输出` | 报告编号、报告名称、材料范围、输出格式、章节顺序、章节名称、内容类型、展示字段、内容要求、结果排序、配置状态、备注 |

不添加隐藏业务 Sheet、宏、单元格 JSON 或让业务人员维护内部 key、工具 ID、向量参数和执行路由。填写说明可以存在，但不能被解析成规则。

### 3.1 材料名称与材料类型

`材料名称` 是场景中的业务材料位，可以写“主合同”“补充协议”等。`材料类型` 是发送给 8018 的 `doc_type`，必须来自 8018 当前 `GET /supported-types` 返回的目录。

两者没有通用一对一关系。系统不得默认“主合同=合同”“结算协议=结算报告”，也不得把材料名称直接复制到 `material_type`。配置页面使用真实目录下拉；目录读取失败时显示外部服务错误，不使用内置列表伪装可选。Excel 中填写的材料类型在发布前按真实目录校验，无法校验时明确标为未验证并阻断依赖 8018 的可执行发布。

8018 的实际类型数量和具体名称是外部易变事实，不写死在 profile、文档或前端。

### 3.2 产物来源

`03_字段抽取.产物来源` 是可选列，目前只定义 `印章识别`。留空表示常规字段抽取；填 `印章识别` 表示该字段取自印章识别产物。

系统必须靠该显式声明确定证据来源，不能根据字段名是否包含“签章主体”猜测。旧 profile 没有该列时继续按旧语义读取；缺少来源声明的旧配置不能据此保证会触发主体检索。

## 4. Sheet 与列匹配

profile 中每个 Sheet 和列都定义 canonical `name` 与有限 `aliases`。匹配规则如下：

- 去除首尾空白后做确定性匹配；不使用模糊匹配、向量或 LLM 猜表头；
- 列顺序可以改变；语义由表头确定，不由列位置确定；
- canonical 名或任一 alias 必须唯一映射到一个内部 key；
- 一个语义出现两列、一个表头同时命中多个语义、缺少必需列时明确报错；
- 可选列可以不存在；新增的未知列保留在来源快照并在预览中标明“未参与解析”，不能悄悄改变规则；
- Sheet alias 只解决名称写法，不改变该 Sheet 的列契约；
- 错误返回 profile、Sheet、真实行列、单元格、原值和原因。

别名是版本化外部协议。新增别名需要明确证明是同一语义；不能为了让某个文件导入而把含义不同的列名加入 alias。

## 5. 行、状态和引用

修订节点格式中，一行表达一个材料、字段、检查、风险或报告章节。空白行忽略；有内容的行必须逐行处置。业务编号在同类对象内唯一并保存为 `source_ref`。兼容旧格式时允许有依据地合并或拆分来源行，但必须保存每个来源行到候选对象的映射，不能用结果数量代替完整性对账。

配置状态固定为：

- `已明确`：业务含义完整，可参与发布；
- `待确认`：必须生成可作答问题，解决前不能发布为可执行版本；
- `停用`：保留来源，但不进入当前执行配置。

状态与执行结果分开。系统不能把“待确认”当启用并静默发布，也不能自动补值、删除或停用问题行来通过预检查。

引用规则：

- 多项统一用中文分号 `；`，去除每项首尾空白；空项和重复项报错；
- 材料名称在同一场景唯一；
- 字段按“所属材料 + 字段名称”解析；
- 展示字段写为 `材料.字段`；
- 未知或不唯一引用明确失败；
- 空白不代表“全部”，新增材料不会自动进入旧规则；
- 名称中不得使用会与引用语法冲突的 `.、；、;、+`。

## 6. 确定性检查

文件格式、大小和重复检查使用原始上传的真实属性：

- 格式：至少核对声明扩展名和内容类型；若未做文件字节鉴定，必须明确写“按声明判断”，不能称为真实内容鉴定；
- 大小：读取真实字节数，按规则明确的 MB 或 MiB 单位比较；
- 重复：使用内容哈希，只与同一任务其他材料位的当前上传比较，并排除自身上传 ID。

图像清晰度、页码连续、有效签章和骑缝章等检查只有在注册工具具有真实输入、明确算法和已确认标准时才能执行。能力或标准缺失时返回无法判断，绝不默认通过。

数值和日期规则使用 Decimal 或明确日期类型：

- `0` 是有效差值，不能因真假判断被忽略；
- 相等：`|左 - 右| <= 允许差值`；
- 不大于/不晚于：`左 - 右 <= 允许差值`；
- 不小于/不早于：`右 - 左 <= 允许差值`；
- 日期差值单位为天；金额差值必须与归一化金额口径一致；
- 缺失值不当零，不默认人民币、元、汇率或百分比；
- 大写金额保留原文和可核验数值，未确认换算口径时不得按字符串比较。

对 `contract_review_v3/v4` 而言，历史解析约束是：`对照内容` 只支持单字段或 `字段 + 字段 + ...`，04 的字段属于同一材料，05 右侧加数属于同一对照材料；使用 Decimal 加总，不执行 Excel 公式、Python 表达式、`eval`、减乘除或跨多份文件汇总。这不是平台内核边界；新场景按已发布关系模型表达一元、二元、多元/集合输入及跨材料实例，能否执行仍由场景配置和真实能力目录决定。

## 7. 风险和报告

在 legacy Profile 中，风险来源只在检查行维护，`06_风险评定` 不重复保存第二份来源列表。新场景可按 09 的关系模型分别保存规则输入、风险触发和背景关联；没有来源仍是配置问题。

“任一关联检查不合格”：存在确定不合格即成立；没有不合格但存在无法判断，则风险无法判断。“全部关联检查不合格”：全部适用来源都确定不合格才成立；存在确定合格则不成立；来源不完整时无法判断；全部不适用时风险不适用。

`07_报告输出` 一行一个章节。同一报告编号下，报告名称、材料范围、输出格式和结果排序必须一致；章节顺序是该报告内唯一正整数。冲突不能取第一行或用空白继承。

系统事实报告属于固定能力，即使没有启用的业务报告章节也必须存在，并明确标注业务章节未配置。`07_报告输出` 配置的是额外的业务报告及章节；零业务章节不能导致任务没有任何报告，也不能被描述为完整业务报告。

报告只读取同一输入修订下当前有效的事实、规则结果、人工结论和风险，不重新调用模型改判。材料范围按实际结果涉及的材料过滤，跨材料规则保留两侧证据。内容要求只影响表达，不能新增审核条件。

输出格式必须有注册并实现的真实渲染工具才能发布和下载。未注册或未实现的格式不得显示为已完成；规则库 Excel 导出不是审核报告。

## 8. 导入、编辑、发布和导出

同一配置对象无论来自 Excel 还是页面编辑，都进入同一种草稿、引用校验、能力校验和 manifest 编译。完整链路必须保持语义：

```text
Excel 导入 -> 草稿 -> 页面编辑 -> 预检查 -> 发布 -> 任务快照 -> 执行
                                             -> 配置导出 -> 再导入
```

不得在任何环节丢失 profile 版本、`source_ref`、材料类型、产物来源、Decimal 原精度、全部加数、报告分组或配置状态。导出选择原 manifest 的 profile 版本；只有显式转换才生成新格式，且要展示差异。

导入成功只表示结构已读取；引用通过只表示可编译；发布成功只表示形成不可变配置；这些都不证明真实材料审核结果正确。

## 9. 运行期路由

编译期根据检查项目、字段类型、合格要求和明确参数，解析为统一工具注册表中的固定 `tool_id`、输入、产物依赖和判断方式。运行期只执行冻结计划，不让 LLM 临时选择规则引擎、RAG 或其他路径。

| 检查 | 取证 | 判断 |
| --- | --- | --- |
| 文件格式、大小、重复 | 原始上传属性和内容哈希 | 确定性工具 |
| 金额、日期、明确字段比较 | 当前有效字段事实 | 确定性工具 |
| 印章主体核对 | 当前任务、材料和产物范围内的印章主体候选 | 相似度排序，工作人员作结论 |
| 条款语义 | 已有字段事实或明确正文证据 | 现有 LLM 校验，必要时人工复核 |
| 风险和报告 | 当前有效规则结果与人工结论 | 确定性汇总和渲染 |

条款语义审核不等于条款 RAG。本轮不建设合同全文向量检索、条款检索、通用问答或 LLM 主体裁决。

## 10. 印章主体检索

索引只对印章识别产物中的主体名称生成向量。页码、坐标、置信度、印章类型和条目序号不拼入向量文本，但原始产物及定位信息完整保存。识别出的不同条目都保留，不能只取第一项或按相似度自动合并。

候选必须先由服务端限定：当前任务、规则材料范围、当前上传版本、产物内容哈希、索引版本、模型和向量维度；再在候选内计算相似度。禁止跨任务或跨版本检索，也不能先全库查出后交给前端过滤。

相似度只用于排序，没有“超过阈值即一致”。工作人员保存一致、不一致或证据不足，并记录所选候选、双方原文、理由和当前待办版本。模型缺失、维度不兼容、产物损坏、没有识别主体、未建索引和索引失效是不同状态，必须分别暴露。

材料替换、移除、补传或产物重建使旧索引退出当前检索；历史记录保留。人工修改待核对字段只使依赖结果重算，不伪造或重写原始印章产物。
