# 规则库与审核执行契约

`backend/config/unified_profile.json` 是系统内部执行协议。每个场景保存独立的 `schema_key`、`schema_version` 和 `schema_json`；当前适配器支持 Sheet 展示名、Sheet 别名和列别名，模板生成与导入均读取场景 Schema。场景还选择实际使用的 Sheet、绑定节点并填写内容；未绑定的 Sheet 不参与转换、生效或执行。新增任意业务列和改变内部字段类型尚未支持。

## 模板

| Sheet | 内容 |
| --- | --- |
| `00_填写说明` | 固定排除的说明页 |
| `01_材料位`、`02_文件处理规则`、`03_字段` | 材料、文件检查和抽取字段 |
| `04_文件内部校验规则`、`05_文件交叉校验规则` | 单材料和跨材料检查 |
| `06_计算定义`、`07_计算参数`、`08_计算判定` | 公式、输入与结果区间 |
| `09_风险规则`、`10_报告模板` | 风险来源与报告章节 |

业务编号来自 Excel。跨表引用可填写业务名称或编号，系统按当前规则库精确匹配，重名或不存在时明确报错，内部统一保存稳定编号；计算规则用同一 `CAL-` 编号关联 06/07/08 三表。内部校验一行可展开到多个适用材料，分支以材料区分。新规则使用业务编号 `rule_code`；历史 `rule_key` 保留以读取旧任务和版本。

导入时冻结场景 Schema，按已绑定 Sheet 独立转换并合并候选。Sheet 与列的映射由程序按场景协议精确匹配，歧义交给用户确认；LLM 不决定字段归属。停用行保留原单元格和来源，不生成可执行规则；待确认行必须形成可处理问题。候选修正、排除和配置生效不能悄悄补默认值。引用歧义、重复编号、缺少依赖、节点成环、计算区间重叠及未处理问题在生效前明确报错。未知列的处置口径尚待确认，见[状态台账](当前状态与问题台账.md)。

Excel 的 `03_字段` 只描述业务字段，不承载抽取实现细节。导入时按字段类型自动选择策略：文本、条款和大写金额保留原文，金额、日期和是否值由后端确定性转换。需要一个字段返回多个业务属性时，在场景或方案字段配置中选择结构化抽取并填写 JSON Schema；LLM 只负责按 Schema 提取，后端校验结构，并要求每个有值的顶层属性分别提供原文证据。再次导入同一场景时，系统按稳定字段编号保留已配置策略；字段类型与原策略冲突时明确报错。

## 执行与冻结

场景配置完整时保存即生成不可变版本，版本同时冻结场景 Schema 和每个节点的字段、规则、计算执行契约。创建任务冻结方案的完整 manifest 和范围；执行只读取任务快照。节点依赖由场景配置，生效前检查，运行期按依赖就绪调度。无配置节点记为跳过并说明原因，不视为检查通过。普通节点目前逐个等待确认，用于调试执行结果。

公式仅支持 `+ - * /`、括号和明确参数引用，不执行 Python、`eval` 或 Excel 任意公式；无默认单位、币种、汇率或缺失值。规则结论应提供标准、实际输入、比较过程和证据。外部服务调用失败或结果未知时显式报错，不伪造成功或自动重发未知状态的作业。

文件格式、大小和同任务重复内容可按现有真实输入判定；清晰度、页码连续、签章与骑缝章缺少业务判据时为不可判定。印章主体检索只返回候选，人工确认结果与相似度分别保存。
