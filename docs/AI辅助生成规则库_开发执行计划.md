# AI 辅助生成规则库：开发与维护约束

更新日期：2026-11-05。本文替换此前“使 AI 编制贴合系统配置”的错误设计；维护者及 Claude 以本文定位和当前实现文档为准。当前实现与验证边界见 [AI 辅助生成规则库](AI辅助生成规则库.md)。

## 必须遵守的产品方向

规则库首先是给人看的业务文档。AI 编制负责规范业务表达、组织条款和暴露真实业务歧义；后续现有 LLM 导入解析才负责转换系统配置。

完整链路：上传业务 Excel → AI 整理编制 → 人核对、修改和补充 → 下载普通 Excel → 用户可选择进入已有场景导入解析。

不得把两次转换合并成“先生成执行 JSON，再反向展示给用户”。内部 JSON 可以用于保存表格、编辑定位和来源关联，但内容应是业务正文。

## 功能要求

| 环节 | 应有行为 |
| --- | --- |
| 入口 | 规则库管理右上角「AI辅助生成规则库」，不新建顶级菜单 |
| 记录 | AI编制记录独立分页筛选；原导入文件列表照常使用 |
| 输入 | 一份业务 Excel、可选业务背景与编制要求；不要求先选场景 |
| 开始 | 「上传并开始 AI 编制」明确依次上传与提交后台命令；失败保留真实记录 |
| 进度 | 使用已有后台操作和查询，不用前端假进度或查询失败自动重新 POST |
| 内容 | 按实际业务主题分表、中文栏目和完整条款；不固定表数或模板 |
| 核对 | 搜索条目、查看正文、原文出处、修改名称/栏目/条目、新增及删除 |
| 歧义 | 待明确事项关联业务条目，用户只补充答案，由 AI 同步修改正文、关联与事项 |
| 下载 | 有修改时先保存再冻结下载；历史文件始终是历史内容 |
| 场景 | 用户显式选择已有场景，从冻结 Excel 创建原有导入作业 |
| 错误 | 上传、模型、保存冲突、下载、场景读取与导入错误明确可见 |

页面以用户动作和业务名称组织，不展示无信息价值的长编码。数量与主要动作横向呈现，正文可展开或进入编辑弹窗完整查看；分页是展示方式，不是业务条目上限。小屏可换行，不能把操作藏在技术说明里。

## AI 编制范围

采用应用内两阶段编制加独立内容复核的固定工作流，不新增运行时 Skill 引擎或自主 Agent 框架：

1. 识别全部非空业务工作表中的要求、真实来源及需要业务确认的问题。
2. 根据同一完整原文和第一阶段清单，编制可阅读的业务表格。
3. 独立核对成文与原文的内容一致性、完整性、关联及误报事项，有依据纠正一次；仍不通过不交付候选稿。

可以规范句子、明确原文已有的主体和条件、合并重复要求、连接原文明确的跨表关系；必须保留独立条件、边界、不等号、公式、单位、适用范围、例外、状态、原编号和业务处置要求。

不得补造政策、阈值、算法、企业事实或审核结论；不得为迁就系统工具能力修改或删除业务要求。缺少业务口径时明确提问，能整理的部分继续完整表达。不存在报告要求时不补通用报告大纲。

不得要求编制结果建立材料/字段/计算/规则/报告五类执行目录、字段引用、执行方式、工具授权、参数来源或系统输入缺项。这些属于现有导入解析与执行模块。

真正未明确的业务问题保留在 issues，不阻止业务文档保存、下载或进入原解析流程。补充通过可选 issue_id 绑定既有事项，后端必须实际应用到相关正文并复核，不得只改状态或保存答案就声称完成；答案不足则具体追问，原版保留。

## 数据与一致性

现有 job 保存当前文档及输入，export 保存不可变快照和文件，import 保存与真实导入作业的关联。多轮修改增加 message 与 revision 两张表：消息绑定实际操作和文档版本，修订保存只追加快照；状态仍从后台操作读取。2026-11-04 经授权完成迁移，源码与实际开发库均为 `0007_generation_assistant (head)`，结构校验和新表元数据比较通过；实际 DDL 已回写 schema.sql。

原始 Excel 与用户编制输入提交后不改写。当前文档每次保存递增版本；导出绑定准确版本，旧导出不被新保存覆盖。上传、开始编制和用于场景各自使用现有幂等机制，不因网络响应丢失重复受理。

失败与中断的详情必须有显式「重试 AI 编制」入口，无需重新选择原文件。版本一致则在原记录重跑完整编制；旧版本无文档时由重试接口复用原件和原输入创建当前版本目标并跳转，原记录不改写。同一原记录和目标版本只建一个重试目标，已执行中或成功的目标直接复用；禁止重复调用模型、覆盖成功文档或宣称断点续编。新目标与后台命令共用请求事务，提交后才调度；文件缺失或变更明确引导重新上传。失败重试本身不新增表或迁移，对话与修订使用上文两张新表。

当前文档为 `rulebook_generation_v2`，新增带默认值的条目性质、稳定业务编号、明确关联和编号流水；旧业务文档缺省读取但不自动保存。提示词 `rulebook_generation_prompt_v9`、助手 `generation_assistant_v11`、导出 `rulebook_generation_xlsx_v10`。来源关联行只放在 `source.origin.related_rows`；入口可合并确定的错层关联行，之后完整校验来源和引用。结构或来源问题最多反馈纠正一次，不忽略未知字段或补造主来源。不把旧系统配置 JSON 解释为业务表格。

首轮默认直接整理并交付。用户对话提出修改时返回有限的实际编辑操作，基于冻结版本应用到副本，结构与来源校验后复核业务变更，成功才原子保存快照与回复。普通询问不改文档，无实际修改不增版本；没有真实问题不显示空问题入口。已有编号沿用原值与规律，仅缺号由模型按原编号规律或业务内容补充；程序不另造一套编制编号，页面与导出统一使用原编号；保持未涉及条目，已有出处不伪造。恢复历史创建新版本并保留编号流水上界；新表不得用于维护第二份可编辑正文。

纠正协议必须明确编辑基准：结构校验失败时不得留下部分操作，内容复核失败时在合法候选稿上补充修复，不从原版应用第二轮增量导致前轮丢失，也不重放新增/删除。最终复核对比冻结原版与合并结果。修改正文时同步备注、事项和来源；事项按原身份原位更新，范围变化允许依据真实原文调整出处，不为排序改号。条目的原始来源类型、位置与需求引用保留；当前编制说明可随实际修改更新，省略时保留，不能将旧冲突描述强制恢复。原文或明确用户补充足以解决的问题可直接解决并注明依据，缺依据的业务标准不得补造。解释不能用于跳过未通过的修复。失败原因应区分结构与内容一致性，不统一误报来源错误。

材料整理使用既有材料行及局部元数据编辑来维护性质和关联，由程序按需生成目录，优先复用原材料表与已有编号关联，避免重复列和目录；不另造重复材料行或手抄编号清单。原文明确涉及多个材料的规则要保留完整关联，停用和待确认状态保持原样。局部元数据操作不得改写无关正文、已有原编号或出处；缺少编号时可由模型通过 business_code 补充，并与原编号栏同步；新关联仍需真实身份及业务依据。回复摘要区分正文、编号关联和事项的变化。

编辑器内部身份不让用户填写，不输出到 Excel 正文。原文目录用于溯源，不能冒充执行规则；用户有意删除或修改正文时不以模型阶段覆盖要求阻止操作。来源沿用及用户修改标记由服务端维护。

## Excel 要求

- 使用已有 openpyxl 生成普通 `.xlsx`，不执行模型代码、不让模型生成 Base64 或任意存储路径。
- 按业务命名工作表与栏目；中文正文完整可读，不塞机器 JSON、内部引用或工具枚举。
- 正文、真实编号、关联、编制说明、确认说明和未明确事项保留；表与栏目说明留在编辑文档中，不重复拼进 Excel 表头或额外大标题，不再自动附加使用说明表。
- 保留原始公式文字，不生成可执行公式；真实业务编号按原文保留。
- 以真实上传原件为样式参考，按来源表、行与栏目匹配字体、填充、边框、对齐、数字格式、列宽和行高；原分组可准确对应时保留，不因编号前缀硬编码。新栏目和辅助表沿用原表风格，禁止自行增加配色、斑马纹、大标题或说明行。保留原冻结、筛选和打印设置；长正文超出 Excel 原生容量明确报错，不截断。
- 同版本复用真实产物，缺失或哈希不一致明确失败。页面可以按冻结快照即时下载原表样式；不得用当前正文替代历史内容、覆盖原文件或为排版增加业务修订。重新排版前核对上传原件大小与哈希，不调用模型。
- 辅助表与业务表重名时调整辅助表，不覆盖业务表。

## 开发边界与编码规范

先读根 `AGENT.md` 和相关当前文档；只读核对分支、工作区，保留用户与其他开发者未提交修改。禁止 reset、清库、无关格式化和覆盖不属于当前工作的文件。

后端遵守 controller / dto / schema / model / crud / service 分层，SQL 仅在 crud；普通请求与后台执行按现有事务约定管理。后台模型调用期间不持有生成作业行锁，返回后重新核对输入和操作当前性。

前端沿用 Vue 3、TypeScript、Element Plus、已有路由和错误展示。类型与后端文档契约同步；保留草稿版本冲突、离开提醒、上下文隔离和操作幂等。编辑弹窗同样受保存与输出锁约束，不能通过弹窗绕过。

只改编制领域、页面、导出及必要的导入文件衔接；严禁为了让生成结果“适配”而修改原导入提示词、执行契约、规则语义、审核任务图、字段核对或取值 CSV。不得直接把编制文档写入场景草稿或绕过确认发布。

导入解析本身的内容职责识别已按用户另行要求调整，约定见 [规则库与审核执行契约](规则库与审核执行契约.md)：区分真实业务动作与材料说明、字典、映射并保留归属。这属于导入职责，不把五类执行分类反加到人读文档的编制阶段。

禁止新增任意数量/轮次上限、静默 fallback、模拟成功、吞错误或自动补零。文件与来源校验用于真实结构和身份，不增加业务合理性审查。未知内容明确说明，不凭猜测加入业务规则。

本次仅允许新增消息/修订两表对应的迁移与编制模块能力，不新增依赖、无关迁移、批量清理或部署。仅在用户明确授权后运行测试、类型检查、构建、服务、浏览器、数据库、模型或外部接口；未授权时做静态核对并明确运行验证未完成，不假报通过。

## 审查与交付标准

| 核对项目 | 判断标准 |
| --- | --- |
| 面向人阅读 | 不懂系统字段和工具的业务人员也能核对条款 |
| 语义完整 | 原文主体、条件、边界、公式、范围、状态和例外未无说明丢失 |
| 业务歧义 | 问题确实来自原文，已有明确口径不误报；不以技术绑定问题干扰用户 |
| 可修改 | 正文和业务表格可编辑，确认说明真实保存并导出 |
| 可追溯 | 原文 Sheet/行号真实，用户新增与编辑标记明确 |
| 输出一致 | 下载内容来自准确已保存版本，旧文件不被新编辑覆盖 |
| 独立解析 | 选择场景后走原 Excel 解析，未直接写入执行配置 |
| 历史数据 | 未转换、改写或删除旧文档、原件及已有导出 |
| 失败可见 | 网络、模型、文件、版本及场景错误能看见真实原因 |
| 验证诚实 | 静态语法通过不等于业务质量、视觉或真实链路通过 |

交付说明写清实际修改、运行证据及未运行的部分。不提交或推送未获授权的改动，不在文档中把旧验证记录当作本轮运行结果。当前迁移、58项本地回归、前端类型检查/构建及专用数据浏览器操作通过；另经授权完成真实合同样本重新上传和首轮、对话修改、正文与事项同步修复、业务补充、只解释、版本恢复与历史文件不变及页面下载核对；单样本结果不证明其他布局或后续场景解析质量，完整范围见实现文档的验证边界。
