# 任务取值 CSV 维护说明

新任务使用格式版本 7。在任务目录下，只有一张 CSV：`values/current/values.csv`。它保存当前有效的字段值和计算结果，每行对应一个事实版本。文件采用 UTF-8 BOM 和中文列名，可按业务编号、名称、材料、期间、报表口径和主体范围定位。

| 数据 | 保存位置 |
| --- | --- |
| 当前有效字段值、计算结果、单位和币种 | `values/current/values.csv` |
| 字段候选、原始写法、抽取证据和已退出当前位的事实 | `values/history.json`；通过记录 ID 查询 |
| 规则结论、产出明细、缺项、原文引用和诊断 | 数据库 `rule_result`；业务载荷在 `result_json.business_result` |
| 人工修改记录、事实索引、报告 | 原有数据库记录 |

新任务不再生成 `rule_results.csv`、`rule_items.csv`、`value_details.csv`。版本 6 的任务继续读写原有四表，不自动转换或删除旧文件。当前取值文件和历史文件的路径都登记在 `audit_task.value_file_json.batches[0].files`。

## 取值与缺项

金额和日期以带类型的可读值保存；结构化字段只占一个 JSON 单元格。0 和 false 是有效值。没有可复用值的字段不进 CSV，字段状态、证据和诊断仍可在任务详情查看。配置声明与正文实际识别的口径分列，不互相覆盖。用 Excel 打开时，把编号和高精度取值列按文本导入；不要直接编辑系统生成的文件，人工修改通过字段核对保存。

字段比较和计算按声明读取当前事实。必要值不可用时记录缺项，其余规则照常；如需补值，使用字段核对或抽取重试。仅声明材料范围的正文核对规则按已声明范围阅读原文，不把这种读取用作缺失字段的补抽。

## 写入与恢复

保存当前值、替换材料、重跑和人工纠错时，退出当前位的取值从 CSV 移入历史，原 ID 不变。文件写入先落临时文件，再原子替换；跨进程任务锁和事务快照覆盖 CSV 与历史文件。保存点或事务回滚会恢复对应文件和清单。文件与数据库没有跨介质事务，强制结束进程、断电或磁盘故障后依赖备份恢复。
