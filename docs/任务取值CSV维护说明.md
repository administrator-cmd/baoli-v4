# 任务业务取值文件

业务文件采用 UTF-8 BOM、中文列名。日常查看先看 `values.csv` 和 `rule_results.csv`，不需要解析模型返回 JSON。当前格式版本为 3，每次写入在 `tasks/{task_no}/value_batches/{batch_id}/` 下生成独立六表批次，路径按生效顺序登记在 `audit_task.value_file_json.batches[].files`。

| 文件 | 每行含义 | 主要业务列 |
| --- | --- | --- |
| values.csv | 一版字段候选、字段有效事实或计算结果 | 业务类别、业务编号、名称、材料名称、期间、报表口径、声明类型、取值说明、原文、候选值、有效值、单位、币种、修订号、写入时状态、取值来源 |
| rule_results.csv | 一次保存的规则结论 | 业务编号、名称、材料名称、规则类型、审核要求、计算公式、结论状态、结论原因、风险等级、风险处置、处理建议、各类明细数量 |
| rule_basis.csv | 一条判断依据，也包括计算过程 | 业务编号、名称、核查项、实际取值、依据说明 |
| rule_outputs.csv | 一项实际产出 | 业务编号、名称、字段名称、产出材料名称、产出编号、原文、产出值、字段状态、产出单位、产出币种 |
| rule_missing_items.csv | 一个尚未解决的业务缺项 | 业务编号、名称、缺失事项 |
| value_details.csv | 结构化值的一个属性或数组节点 | 业务编号、名称、业务项目、属性名、数组序号、值类型、值；所属项目及节点关系用于还原结构 |

记录类型、记录ID、写入批次等技术关联列放在表格右侧；按名称、材料、业务编号筛选即可查看。字段候选是抽取原文及待确认取值，字段事实是实际执行输入，两者用途不同；无效候选可以保留候选值，但有效值为空。规则结论不再重复保存整份 verdict，字段事实也不再重复保存模型 judgement。新产出的 extracted_values 展示从产出明细组装，不重复保存。

## 单元格和值类型

可读业务值与类型各自一列，例如“有效值”和“有效值类型”。支持 text、integer、float、decimal、boolean、date、datetime、null、object、array。金额和十进制不经过 float，布尔值写 true/false，日期采用 ISO 格式。导入 Excel 时将业务值列、ID 和编号列设为文本，避免自动转日期、科学计数或截断精度；CSV 引号本身不能阻止 Excel 自动改写类型。

类型列为空表示没有保存该属性；null 表示明确空值，值单元格留空；text 配空白单元格表示空字符串。零值和 false 都是实际值。object/array 的值列留空，在 value_details.csv 按同一记录、写入批次和所属项目维护子节点，不能往该单元格贴 JSON。空对象、空数组保留根节点。缺失类型、非法值、缺明细、重复节点和数组序号不连续会明确报错，不填默认值。

多条依据、产出、缺项分别占行，明细序号从 0 开始。主表的数量必须与实际明细相符。补充业务属性（如工具核查明细、计算定义、风险来源、历史报告正文）逐属性展开到 value_details.csv，不丢失嵌套值和类型。历史转换保留的不同旧结论在“历史结论差异”项目展开，不伪装成当前结论。

## 维护和生效

- 同一记录以数据库批次清单中最后包含该记录的批次为准，读取同一批次的明细。清单顺序决定生效顺序；同一批次不重复写同一记录。历史批次保留，不按业务编号合并不同记录或不同执行批次。
- 业务名称、口径、写入时状态、要求等描述列用于查看和定位，来自任务冻结配置或写入时数据库索引；编辑这些描述不会修改规则配置、数据库状态或当前版本。
- 调整业务规则应修改场景/方案配置；正式纠正字段应使用页面字段纠错入口，它会建立新修订并失效相关输入。直接编辑 CSV 仅适合停机数据修复，不会自动建立修订、同步数据库结论状态、重算下游或更新已生成报告。
- 程序不修改已写批次。停机数据修复时先备份全部生效批次和数据库，保留关联列、记录数量及文件清单；直接修改真实值、原因、依据后，下一数据库会话重新读取。状态列表仍以数据库索引为准，不能只改 CSV 状态列就认为审核状态已变更。
- 六表全部写入、关闭并同步文件后才更新批次清单；清单与业务索引由同一数据库事务提交。事务或保存点回滚后，新文件不在生效清单中，已有记录的旧值继续生效；未引用文件由清理工具在任务停止执行后清理。文件系统与数据库没有分布式事务，提交后的文件丢失或人工改坏仍会明确报错。
- 会话缓存按生效清单增量加载新增批次；回滚使清单回退或分叉时重新读取，避免撤销批次的值继续留在缓存中。

## 旧文件转换

旧三列 payload_json 文件和版本 2 的共享业务表都需要显式转换。新代码不会自动混读或切换引用。转换工具为 `script/migrate_task_values.py`：

```powershell
python script/migrate_task_values.py TASK_xxx
python script/migrate_task_values.py TASK_xxx --apply
```

第一条只读数据库和旧文件、显示待转换记录数；第二条要求任务无活跃后台操作，在独立目录写批次并提交清单引用。两条命令都需要真实数据库连接。本次代码修改没有执行它们。

转换只迁移仍有数据库索引的最后版本；孤立记录、历史追加行及原始封套都留在原文件，不删除。全部原文件登记为 legacy_files，清理工具同时保护全部生效批次、明细表及原文件。转换中失败会暴露异常；数据库提交前不会切换已提交的引用，失败目录不生效。数据库表结构不变。
