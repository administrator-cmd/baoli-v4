# 任务取值 CSV 维护说明

业务取值保存在 UTF-8 BOM、中文列名的 CSV 里。日常查看先看 `values.csv` 和 `rule_results.csv`，不需要解析模型返回的 JSON。

当前格式版本为 6。每个任务固定维护 `tasks/{task_no}/value_batches/current/` 下的四张表，路径登记在 `audit_task.value_file_json.batches[0].files`。每次写入按 `(记录类型, 记录ID)` 合并，再逐个原子替换四张表，不再新增批次目录。

| 文件 | 每行含义 | 主要业务列 |
| --- | --- | --- |
| `values.csv` | 字段候选、字段有效事实或计算结果 | 业务类别、业务编号、名称、材料名称、期间、报表范围、主体范围、声明类型、取值说明、取值来源、原文、候选值、有效值、单位、币种、原文依据 |
| `rule_results.csv` | 一次保存的规则结论 | 业务编号、名称、材料名称、规则类型、审核要求、计算公式、风险处置、处理建议、原文依据、展示协议版本、各类明细数量 |
| `rule_items.csv` | 一条判断依据、一项实际产出或一个缺失事项 | 业务编号、名称、材料名称、明细序号、明细类别、核查项/产出编号/缺失事项、实际取值、依据说明、原文、字段名称、产出材料名称、产出值、字段状态 |
| `value_details.csv` | 结构化值的一个属性或数组节点 | 业务项目、属性名、数组序号、值类型、值 |

记录类型、记录 ID 等技术列放在表格右侧。按名称、材料、业务编号筛选即可查看。

字段主记录还会把模型从正文实际识别到的期间、报表口径、主体范围和单位保存为补充属性（`actual_period_scope`、`actual_statement_scope`、`actual_entity_scope`、`actual_unit`），在 `value_details.csv` 中按现有补充属性规则展开；四张表的列结构不变。配置声明的期间/口径仍保存在“期间”“报表范围”“主体范围”“单位”列，两者不互相覆盖。

规则补取的 `input_resolutions` 作为规则主记录补充属性保存，并按现有树编码写入 `value_details.csv`；每项保留缺项身份、真实取值与已校验的来源。四张表的列和格式版本不变。

`rule_items.csv` 用“明细类别”区分三类：判断依据（basis）、实际产出（outputs）、缺失事项（missing_items）。同名不同义的列按各自标签保留，例如“实际取值”属于依据，“产出值”属于产出。

## 值类型

可读值与类型各占一列，例如“有效值”和“有效值类型”。支持 text、integer、float、decimal、boolean、date、datetime、null、object、array。

- 金额和十进制不经过 float；布尔值写 true/false；日期用 ISO 格式。
- 类型列为空表示没有保存该属性；null 表示明确空值；text 配空白单元格表示空字符串。
- 零值和 false 都是实际值。
- object/array 的值列留空，在 `value_details.csv` 按同一记录和所属项目维护子节点，不能把 JSON 贴进单元格。
- 原文依据是唯一允许放在单个 JSON 单元格里的复杂值。

导入 Excel 时把业务值列、ID 和编号列设为文本，避免自动转日期、科学计数或截断精度。

## 写入与恢复

- 写入先写临时文件，再逐个原子替换；读取和写入共用跨进程任务锁。
- 四张表全部落盘并关闭后才更新文件清单；清单和业务索引在同一个数据库事务提交。
- 保存点失败只恢复对应层级；外层事务回滚能恢复整批文件。
- 提交后只清理临时快照。快照被占用时记录 ERROR 和剩余路径，不把已提交的数据报成失败。
- 数据库和文件系统没有跨介质事务。进程被强制终止、断电、磁盘故障不在恢复保证内。
- 格式版本不是 6 的任务会明确报 `TASK_VALUE_FORMAT_UPGRADE_REQUIRED`，不会静默降级。
