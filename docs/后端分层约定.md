# 后端分层约定

代码按实际职责分层，不建空接口、repository 层或额外包装。

## 目录

| 目录 | 职责 |
| --- | --- |
| `app/main.py` | 创建应用、注册路由、启动检查 |
| `app/api/routes.py` | 汇总各模块 router |
| `app/modules/<业务>/<实体>/` | 该实体的路由、模型、数据访问和服务 |
| `app/core/` | 配置、数据库会话、CRUD 基类、ORM 基类、响应基类 |
| `app/domain/` | 配置结构、引用编译、值转换、工具目录；不访问数据库 |
| `app/graphs/` | LangGraph 任务图和单条规则执行器 |
| `app/integrations/` | LLM、文档解析、OCR、印章等外部服务 |
| `app/operators/` | 本地工具算子 |
| `app/services/shared/` | 跨业务共用能力 |
| `app/middleware/`、`app/common/`、`app/runtime/` | 请求上下文、异常、启动检查 |

实体目录固定为：

```text
modules/<业务>/<实体>/
  controller.py   HTTP 路由
  dto.py          请求参数
  schema.py       响应模型（VO）
  model.py        SQLAlchemy 实体
  crud.py         数据库读写
  service/        业务编排
```

请求用 `dto.py` 的 `XxxRequest`，响应用 `schema.py` 的 `XxxResponse`；分页和列表筛选参数在 `app/schema/query/`，通用响应结构在 `app/core/base_schema.py`。

## 依赖方向

controller → service → crud → model。

- controller 只处理 HTTP：入参、依赖注入、响应组装。
- service 负责业务编排；不直接执行 SQL，也不调用 Session 的查询、写入方法。需要跨实体读取时用对应 CRUD 的 `get_of`，提交与回滚也通过 CRUD。
- crud 是访问数据库的唯一位置，SQL 和会话操作都放这里。
- domain 不导入 modules；integrations 只被 service 调用；graph 只调用 flow 函数。
- 不做包级重导出，调用方从具体模块导入。

数据访问示例：

```python
task = AuditTaskCRUD(db).by_no(task_no)
AuditTaskCRUD(db).commit()
```

## 命名与注释

- 函数名说明动作和对象，类说明职责，避免“本实体服务”一类空泛描述。
- 同一份身份或缺项清单由一个函数生成，上下文和保存校验共同使用。
- 注释只解释业务约束、事务边界及反直觉原因，不重复代码、不记录修改过程。
- 简单函数用一句话说明；搬迁后删除空节标题、过期路径和连续空行。
- 错误明确上抛或交回既有模型修正流程，不吞异常、不伪造成功。
