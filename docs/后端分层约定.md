# 后端分层约定

本项目按 FastAPI 和 SQLAlchemy 的实际职责组织代码，不要求空的接口、实现类或额外包装层。

## 目录职责

| 目录 | 职责 |
| --- | --- |
| api | HTTP 路由、入参、依赖注入与响应组装 |
| services | 业务用例、执行编排、事务边界和视图组装 |
| repositories | 可复用的数据库查询与配置持久化 |
| entity | SQLAlchemy 实体，与 database/schema.sql 对齐 |
| schema/dto、schema/query、schema/vo | 写操作输入、查询条件、响应模型 |
| domain | 配置形状、引用编译、值转换及工具目录 |
| graphs | 固定任务图和单条规则执行器，不保存持久化 checkpoint |
| integrations | LLM 与文件处理、OCR、印章等外部服务适配 |
| operators | 模型可选择的本地工具实现 |
| middleware、common | 请求上下文、异常等公共能力 |

API 将业务操作交给服务层。服务可以使用 repository 或直接组织 ORM 操作；已有服务层查询不需要为分层再包一层。数据库实体不作为接口 response_model，Pydantic 模型不作为数据库实体。

场景、方案和任务的列表或详情读取分别由 scenario_query_service、plan_query_service、task_query_service 负责；原管理服务保留写操作、编译和事务。场景与方案共用的计算定义读取、引用改写位于 domain/calculation_config.py，方案计算启停解释位于 domain/plan_calculations.py，不依赖场景管理服务的私有函数。最新已发布版本查询统一在 scenario_repository。

管理列表的公共分页结构位于 common/pagination.py，分页入参校验仍在 schema/query；筛选、计数、排序保留在对应查询服务。报告下载只共用 api/downloads.py 的响应构造，各接口分别校验报告存在、正文可用和当前性。

## 审核模块

services/audit 按职责分为 commands、flow、rule_execution、rule_results、facts、views、state、evidence、artifacts、shared 等模块。命令入口组织写操作，flow 编排模型和工具，rule_execution 读取上游数据并保存产出，rule_results 保存规则结论、CSV 业务负载及证据关联，facts 处理事实索引及字段纠错，views 组装只读结果。rule_results 不提交事务，提交边界由 flow 保持。

规则结果状态集合和模型循环状态统一位于 domain/audit_vocab.py。`COMPUTED` 表示“已完成产出”，具体抽取或报告语境仍按实际产物展示；它不等于审核通过。前端对应口径集中在 constants/auditStatus.ts，规则详情抽屉与列表通过 utils/auditRulePresentation.ts 复用纯展示逻辑。

graphs/audit_graph.py 只组织任务固定生命周期，在 execute_rules 中串行遍历依赖计划；graphs/audit_rule_runner.py 负责单条规则的模型与工具循环，通过协议调用 services/audit/flow.py 的真实步骤。图模块不导入服务实现，也不在图回边中遍历规则或模型轮次。

业务取值的 CSV 读写统一经过 services/task_value_service.py；数据库仍管理索引、状态、证据和报告。具体存储边界见[执行契约](规则库与审核执行契约.md)。

审核包通过惰性导出提供命令和视图入口，避免包导入时提前加载 commands 导致循环依赖。

## 错误与请求追踪

错误响应使用 code、message、details、request_id，HTTP 状态码保留失败语义；成功响应不增加统一包装层。

- BusinessError 保留错误码、说明及业务详情，敏感键按 common/exceptions.py 的规则显式脱敏。
- 请求结构错误返回 422 / REQUEST_VALIDATION_FAILED；未知异常返回 500 / INTERNAL_ERROR，完整堆栈留在服务端。
- 请求上下文和 CORS 为响应提供 X-Request-ID；流式响应开始后的异常仍由服务端暴露，不替换成成功响应。
- 前端保留错误码、HTTP 状态和请求编号，区分通信失败、超时、主动取消及非法响应。超时或取消不能推断后台操作成败，后台状态由操作查询接口报告。

事务由对应写服务负责，异常处理不伪造成功。缺少真实输入、外部调用失败或模型输出无法保存时，应保留可定位的错误，不以空值或假结果代替。
