# 术语字典

更新：2026-09-18。性质：`docs/` 内目录名、文件名和分类名称的唯一命名依据。

本文只从现有文档、源码和配置中提取术语，不发明新名词。无法从现有材料确认含义的，
一律标为**待确认**，不得猜测填入。

## 0. 使用规则

1. 目录名、文件名和文档中的分类名称只能使用本字典第 1、2 节的词。
2. 同一概念只能有一个标准名称；其它写法记为该名称的**别名**，只允许在解释历史口径时出现，
   不得作为新的目录名或文件名。
3. 新增术语前先在本字典中查找同义词；找不到才能新增，并同时登记定义和禁止别名。
4. 本字典不改变任何业务术语的含义。文档正文中的业务口径以用户确认和真实运行证据为准，
   本字典只统一**命名**。

## 1. 允许使用的目录名称

只在实际需要分组时使用，不为了凑结构建空目录。

| 目录名 | 收录内容 |
| --- | --- |
| `00-项目说明` | 项目介绍、背景、目标、范围、快速开始 |
| `01-需求` | 功能需求、业务规则、用户需求、需求变更 |
| `02-设计` | 架构设计、模块设计、接口设计、数据库设计、技术方案 |
| `03-开发` | 开发规范、编码约定、环境配置、开发流程 |
| `04-测试` | 测试方案、测试用例、测试报告、缺陷记录 |
| `05-运维` | 部署、发布、监控、故障处理、备份恢复 |
| `06-会议记录` | 会议纪要、讨论记录、决策记录 |
| `07-参考资料` | 外部资料、学习笔记、技术参考、第三方文档 |
| `99-归档` | 已经结束但需要保留的历史文档 |
| `_待确认` | 无法确定归属、用途或是否可以删除的文件 |

**当前实际结构**：`docs/` 采用平铺，没有子目录。8 个文件全部被引用、
零断链，5 份活动文档的路径还被 `CLAUDE.md`、根 `README.md` 和
`backend/app/services/rag_service.py` 引用，因此不按上表重组。
`99-归档` 目录当前不存在：历史评审结论已并入
[当前状态与问题台账.md](当前状态与问题台账.md) 第 7 节，不再单设归档目录。

## 3. 文档类型词

文件名后缀只能使用下表。现状为英文名与中文名并存，本次整理已统一为中文名，
英文名保留为别名以便追溯。

| 标准类型名 | 含义 | 原英文名（别名，只用于追溯） |
| --- | --- | --- |
| 索引 | 目录内容的入口与职责说明 | `README` |
| 评审稿 | 待用户评审的方案，尚未批准 | `design`（`agent-review-design`） |
| 基线 | 历史架构边界与不变量 | `baseline`（`design-baseline`） |
| 契约 | 对外格式协议与执行边界 | `design`（`excel-rag-design`） |
| 规范 | 产品与交互的长期约束 | `spec`（`frontend-design-spec`） |
| 台账 | 随实现变化的状态与问题记录 | `log`（`issue-log`） |
| 摘要 | 历史轮次的合并结论 | `README`（归档摘要） |

禁止在文件名中使用：最终版、最新、新版、临时版、`new`、`old`、`final`、`draft`。

## 5. 已废弃或历史术语

这些词在当前设计中已经不用，只在解释历史轮次时出现。**不得**用作目录名、文件名或新文档中的分类名称。

| 历史名称 | 现状 | 依据 |
| --- | --- | --- |
| 场景版本 | 页面上的「版本」概念已移除，场景只有一份保存即生效的配置 | 当前状态与问题台账 0.1 |
| 方案版本 | `plan_version` 表已删除，方案保存即生效 | 当前状态与问题台账 0.2 |
| 草稿 / 发布 | 三层冻结收敛为一层（任务创建冻结），页面上不再出现 | 当前状态与问题台账 0.1、0.2 |
| 七 Sheet 固定结构 | 只针对既有 Profile，不是所有场景的输入要求 | 规则库与审核执行契约 |
| `TYPE_MISMATCH` | 已下线的自动识别写入，读取时一律按 `TYPE_REVIEW` 归一 | 当前状态与问题台账 1.1 |

## 8. 维护规则

- 新增目录、文件或分类名称前，先在本字典中检索同义词。
- 术语含义来自用户确认或真实运行证据，本字典不代填默认值。
- 发现同一概念出现新写法时，保留一个标准名称，其余登记到第 6 节别名表。
- 本字典随文档整理同步更新；不记录实现进度，实现状态只看
  [当前状态与问题台账.md](当前状态与问题台账.md)。
