# 业务逻辑

系统将业务 Excel 解析为规则库 JSON，再按用户方案中生效的规则审核上传材料。LLM 抽取字段、计算和判断，程序提供数据读取、工具调用及结果保存。

## 场景、方案与任务

| 对象 | 用途 |
| --- | --- |
| 场景 | 管理员维护材料、字段、规则、计算和报告定义 |
| 场景版本 | 显式发布的配置版本 |
| 方案 | 用户基于场景版本调整启停和业务配置 |
| 任务 | 冻结方案配置与执行范围，审核本次上传材料 |

管理员上传 Excel，系统把全部非空 Sheet 交给 LLM。第一轮从 Excel 识别业务 JSON，第二轮对照同一 Excel 原文整理第一轮结果和执行引用；原名称、原编号与来源行随最终配置保留到数据库。管理员在解析结果表格中修改业务要求、切换启用或暂停状态，保存后写入场景草稿，再显式发布。不要求统一表名或表头，没有选表、绑定工作表步骤。

用户从已发布场景生成方案，调整配置后创建任务并上传材料。后来修改场景或方案不会改变已有任务。删除场景移除身份和草稿，已有发布版本、方案、任务与导入记录独立保留。新建方案必须携带幂等标识：响应丢失后重发相同请求返回原方案，不会重复创建。

审核任务采用永久删除：移除任务本身、材料位、全部上传版本与处理产物、字段与事实索引、任务 CSV、规则结果、证据、复核、报告及节点执行记录。正在执行或有活跃后台操作的任务仍拒绝删除。前端不提供已删除列表和恢复入口。

删除保留通用操作日志和创建/复制命令的幂等历史；重发已删除任务的创建/复制命令明确返回 410。文件目录先改名，数据库事务失败时恢复目录，提交后再清理文件；文件清理失败会明确报错并返回剩余路径，不报告删除成功。数据库与文件系统没有跨系统事务，进程异常终止可能留下待清理目录。现有 deleted_at 列不再读写，无需因此重建数据库；旧逻辑删除记录会重新出现在任务列表，可由用户永久删除，代码更新不自动清理现存任务。

方案可修改材料要求、字段抽取、审核规则、计算公式与参数、报告章节和启停状态。审核与计算规则提供业务编辑表单，保存提交完整定义并重新编译方案；字段抽取及报告派生执行项由对应字段、报告定义同步生成。计算结果标识修改时，编辑页同步更新报告、规则和下游计算中的结构化引用，业务原文中的文字引用仍需用户相应调整。

方案配置按材料、字段、审核规则、计算规则、报告章节分为独立页签，各列表支持即时搜索、状态筛选和分页，默认每页 20 条。字段可按材料和数据类型筛选，审核规则可按材料和真实来源工作表筛选，报告章节可按材料和所属报告筛选。切换页签及关闭编辑弹窗保留当前列表条件和页码；编辑或移除使当前页越界时回到有效页。筛选和分页只改变展示，保存仍提交方案的完整配置。

场景和方案的配置列表按真实业务编号自然升序显示，空编号放在末尾，同编号保持原顺序，不另加重复序号；报告章节的业务顺序不因展示排序改变。管理列表与审核结果统一表格字号、内容居中及浅色表头，工作表来源只显示表名，来源行保留在详情。抽取和报告规则的结果编号读取任务冻结配置中的字段编号、报告编号，未配置时不使用内部执行编码冒充。跨任务风险列表与任务风险页使用同一业务编号；风险身份由冻结规则的明确风险角色或风险算子确定，不以是否填写风险等级判断。

字段结果将字段名称与关联材料分列展示。金额和数值类型在列表与详情的标准化结果中使用千分位，按保存的十进制字符串保留小数位，不修改原始值或计算值；账号、编号等文本类型不按数字格式化。数值采用等宽数字，未取到值的说明使用次要文字颜色。当前结果的单位与币种仍有缺失，页面不据字段名称推断或补写单位。

任务风险结果支持按风险结论、风险等级、来源工作表组合筛选，并可搜索编号、风险名称、判断理由和引用原文。分类选项根据实际结果生成并显示各类总数，沿用风险结论的业务名称；未标注等级、未记录工作表可单独筛选。工作表来源读取任务冻结规则的来源信息。筛选无匹配项与未配置、尚未执行、结果失效等状态分开展示。

场景配置页直接查看和修改当前内容，修改后点击发布；不提供草稿与发布内容的切换入口。有草稿时详情和列表数量读取草稿，并显示“有未发布修改”或“尚未发布”；没有草稿时读取已发布配置。发布成功后删除草稿，发布快照与草稿删除在同一事务提交。查看或刷新不创建草稿，编辑保存或确认导入时才生成草稿。

场景计算规则支持新增、详情、编辑和删除，启用、停用及待确认状态在编辑中调整。编辑保留来源和未修改的附加属性；规则编号保持身份不变，结果标识修改时同步更新审核规则、下游计算参数与依赖、报告章节中的结构化引用，业务原文不自动替换。仍被规则、计算或报告引用的计算不能删除，接口明确列出引用对象。修改保存草稿，发布后供新方案使用。

启用项参与执行，待确认和暂停项不执行。待确认项仍可保存和发布，不阻止其他规则；管理员明确启用后才参与执行。

## 审核流程

审核材料为 PDF 或图片，场景规则库 Excel 走独立导入入口。开始审核后，程序先对所有已上传材料完成前置处理，再进入字段抽取、计算、规则校验和报告生成。材料在 8018 校验完成后并行进入两条分支：8010 去章 → PaddleOCR 正文 Markdown，以及 8003 原件印章识别；8003 不读取去章文件，也不等待 OCR。8018、8010、8003 各自逐份处理且站间并行，OCR 作业独立提交和续查，前一份材料进入下一步时后一份就能继续推进。每份材料的四项均成功才算准备完成；失败保留真实原因和已完成产物，其余独立分支收尾后统一阻断审核。模型读取 OCR 正文抽取业务字段，读取 SEAL 产物按规则检查印章，主体一致性规则比较这两份实际来源。

前置处理不由模型选择或触发。全部已上传材料的四项产物就绪后才开始业务规则；服务调用失败明确记录材料、处理步骤及原因，任务阻断，后续规则不启动。重跑复用当前上传版本已有产物，OCR 按原作业号续查，不自动重复提交。单项失败可在材料处理状态单独重试该项，已就绪产物和其他材料不受影响；结果未知的提交须由用户明确确认可能重复调用后才重新提交。未上传材料交由后续规则说明缺失；8018 的类型匹配结论保留给业务规则判断，不增加置信度阈值或人工确认门槛。

字段定义、计算定义和报告章节会编译成执行项，与普通规则一起进入通用规则循环。显式引用决定依赖顺序，报告在其他生效项之后执行；缺少依赖或循环依赖会进入相关规则上下文。

每条规则在导入时确定执行方式：材料检查、字段比较、跨范围比较、组合汇总、风险推导、字段抽取、计算或报告生成。执行方式决定该条规则拿到哪些上下文：组合汇总由程序按来源规则状态计算，不调用模型；风险推导只读取来源规则结果；材料检查只给材料与产物；字段比较和跨范围比较只给声明输入或材料范围。

除组合汇总外，每条规则读取配置和当前真实数据，由 LLM 抽取、计算或判断。比较与计算类规则在调用模型前先检查声明输入：任一输入状态为 NOT_EXECUTED 时，本条直接记为 BLOCKED，原因写明是哪个业务字段未形成取值，不调用模型，也不允许改为直读材料补位。模型需要额外能力时发起原生 tool_calls，程序执行工具并把返回交回模型。结果结构不合法时，错误回填同一规则，由模型修正；单条无法完成时保存原因，其余继续。未知程序异常明确暴露。

同一材料、同一产物来源上连续出现的多条单字段抽取，程序合并为一次模型调用：正文只读一次，一次返回全部字段，再按字段拆回各自的规则结果。程序给本批字段发批次短编号，模型只抄短编号，保存前换回内部字段键；某个编号无法识别时只让对应字段记为未执行，不影响同批其他字段。合并只省去重复读同一份材料，每条字段仍各自保存、各自成败。

任务图只负责固定生命周期，规则顺序根据冻结配置的显式依赖生成一次，同层内按执行方式排序（抽取、计算、材料检查、比较、汇总、风险、报告），由程序逐条执行。每条规则有独立的模型与工具循环、消息和轮次计数，提交结果后下一条才能读取它。规则数量和模型轮次不占用任务图步数，不因正常规则遍历触发 LangGraph 默认 25 步限制；既有模型轮次配置按单条规则生效。

字段值、计算结果和规则业务结论写入本任务的 CSV，后续规则和页面先查数据库索引，再按记录 ID 从 CSV 取值。数据库还保存任务状态、执行诊断、证据原文和报告正文；当前诊断含业务值副本的问题见[问题台账](当前状态与问题台账.md)。

继续执行、字段纠错或材料换版会创建新的版本并让旧执行退出当前位；旧执行记录保留原始结局并显示“已失效”，失败原因不会被改写。“全部重新执行”另建批次重跑全部生效规则，同样让旧执行失效。

可继续的批次包括 BLOCKED、结果已提交但图未推进的 SUCCEEDED，以及失败原因允许重算的 FAILED。FAILED 是否放行看「已提交结果是否仍然可信」：服务重启、模型渠道故障、程序异常、存储暂时不可达都可以沿用原批次；缺材料、缺执行方式、批次对不上等输入或配置问题必须先处理。继续执行复用当前批次，只重跑未完成项及其全部传递下游，已完成的规则保留；报告依赖全部非报告项，会自动加入重跑。保留、补跑、受依赖影响三类数量由服务端算出并展示，页面不自行推导。需要重跑全部规则时使用“全部重新执行”，且需用户确认。

模型渠道故障（网络失败、超时、鉴权失败、配置缺失、流未正常结束）与请求结果未知会停止后续模型请求：当前规则按真实错误记为未完成，已形成的结果照常提交，批次以 `AUDIT_LLM_CHANNEL_UNAVAILABLE` 结束等待继续执行，不写成执行成功。请求结果未知时不自动重新 POST，继续执行前页面提示可能再次产生费用。规则输出格式、证据引用等单项问题仍只影响该条规则。

审核图只保留当次运行的内存状态，不使用持久化 checkpoint，也没有节点确认等待点。人工审核暂不启用，字段纠错功能保留。任务“执行已结束”不等于所有业务检查通过，无法判断的事项仍须显示真实原因。

系统只提供报告下载，不提供列表 CSV、中间值或上传原材料的下载、预览入口。

详细数据与执行说明见[执行契约](规则库与审核执行契约.md)。
