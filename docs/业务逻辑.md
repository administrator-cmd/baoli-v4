# 业务逻辑

系统把业务 Excel 解析成规则库 JSON，再按用户方案里启用的规则审核上传材料。LLM 负责抽取、计算和判断，程序负责取数、调用工具和保存结果。

## 场景、方案与任务

| 对象 | 用途 |
| --- | --- |
| 场景 | 管理员维护材料、字段、规则、计算和报告定义 |
| 场景版本 | 发布后生成的配置快照 |
| 方案 | 用户基于场景版本调整启停和业务配置 |
| 任务 | 固定方案配置和生效范围，审核本次上传材料 |

管理员上传 Excel 后，系统把全部非空 Sheet 交给 LLM。第一轮识别业务对象，第二轮对照原文整理引用和完整配置。管理员可以在解析结果里修改要求、启停规则，保存后写入场景草稿，再发布。不要求固定表名、表头，也没有选表步骤。

用户从已发布场景创建方案，调整配置后创建任务并上传材料。之后修改场景或方案，不影响已经创建的任务。新建方案必须带幂等标识：响应丢失后重发同一请求会返回原方案，不会重复创建。

任务删除是永久删除：任务、材料位、上传版本、处理产物、字段与事实索引、任务 CSV、规则结果、证据、复核、报告和执行记录一起移除。正在执行或有活跃后台操作时拒绝删除。

## AI 辅助生成规则库

管理员可以在「资料管理 → 规则库管理」使用「AI辅助生成规则库」：上传一份业务 Excel（可选业务背景和补充要求），AI 依据完整原文整理成供人阅读和修改的业务工作表、中文栏目、条款正文与待明确事项，不在此阶段生成系统执行配置。

页面「上传并开始 AI 编制」依次保存原件、提交后台模型编制；上传接口本身不调用模型。编制成功后得到第 1 版业务文档，可以搜索、修改条目、调整表格和记录业务确认说明；保存携带版本号，旧页面保存明确冲突。下载前有修改会先保存，导出按版本冻结，历史版本始终下载原内容。

导出文件可以选择一个已有场景创建现有导入作业，此时才由原有 LLM 解析转换系统配置，不会自动写入草稿、发布或创建任务。编制文档的结构、来源、业务问题和编辑规则见 [AI 辅助生成规则库](AI辅助生成规则库.md)；它不使用审核任务取值文件，也不改变现有导入解析原则。

## 审核流程

材料支持 PDF 和图片；规则库 Excel 走单独的导入入口。上传只保存文件。开始审核后，LLM 先识别哪些已生效材料检查只需原文件数据，再调用文件格式、大小或重复检查工具，逐文件给出结论。业务标准取自规则原文，不补固定格式或上限。不合格或暂时无法判定的文件停止后续处理并展示原因，其他文件继续；需要正文或印章的质量检查仍在处理后执行。

材料页分别展示前置质量和处理状态，可筛选需关注的文件，在明细中查看冻结的检查要求、逐文件结论及判断依据。无前置检查不显示为通过，前置检查通过不代表材料内容已全部审核。质量停止的文件需要按原因处理或替换，不能通过处理服务的重试解除限制；技术处理失败仍可在获准处理后单项重试。

材料前置处理分四条线：

- 8018：材料类型校验；
- 8010：去章；
- PaddleOCR：读取去章后的正文；
- 8003：识别原件印章。

8018 完成后，去章与印章并行；去章完成立即进入 OCR，不等待印章。各服务逐份处理，上一份离开后下一份继续。OCR 作业独立提交、独立续查。每份材料四项都成功才算准备完成；失败保留真实原因和已完成产物，其他分支收尾后统一阻断审核。

获准处理的材料准备完成后，按规则声明的依赖执行。质量未通过的文件不抽取字段，关联审核与依赖规则保留未执行原因；报告继续说明实际审核范围和缺项。续跑、字段核对补值和单项处理重试不能解除这一限制。每条规则在导入时确定执行方式：

材料检查、字段比较、跨范围比较、组合汇总、风险推导、字段抽取、计算、报告生成。

组合汇总由程序按来源规则状态计算。比较、计算按声明读取当前事实，缺少必要取值时直接保存证据不足与缺项，其他规则继续；确认未载明可作为存在性检查的事实。需要理解材料正文的规则可按声明范围使用正文。

相邻、同材料同产物、无输入依赖的单字段抽取满足条件时可合批。首轮共用一份正文，逐字段保存结果；修正范围见[批量抽取契约](规则库与审核执行契约.md#批量抽取)。

任务图负责固定生命周期。规则按依赖顺序执行；程序可直接形成的结果不请求模型，单条模型判断和合批抽取各用自己的执行路径。结果提交后，下游才能读取；规则数量和模型轮次不增加图节点。见[工作流细图](资料审核系统工作流.md)。

### 字段核对

抽取完成后，任务停在字段核对等待点（`WAITING_FIELD_REVIEW`）。这是正常等待，不是失败。

页面按材料列出字段名称、抽取原值、本次采用值、单位与范围、原文依据和状态。来源文件按该结果实际证据对应的上传版本显示，不用材料位当前文件名顶替；正文实际识别到的期间、报表口径、主体范围和单位与配置声明分开显示。可以改错值、补填漏抽值、标记“材料中不存在”。

- “保存修改”只写字段，任务继续等待。
- “确认并继续审核”保存剩余修改，记录确认信息，然后在同一批次继续执行计算、检查、风险和报告。
- 仍缺值时页面列出真实缺项，用户确认后才继续；系统不补值，也不默认通过。
- 人工修改会生成新的字段版本，原抽取结果和原文依据保留；人工值不会被模型重新抽取覆盖。

字段或材料版本变化后，原确认失效，需要重新核对。确认只表示采用当前字段版本继续审核，不代表材料真实，也不代表审核通过。

## 结果与重跑

任务结果分两处查：可复用的当前字段与计算值见[任务取值 CSV](任务取值CSV维护说明.md)，规则结论、依据和诊断在任务详情按记录查询。字段列表用「抽取到／未抽取到」展示抽取结果；未执行、不适用等执行状态另行说明。执行结束不表示所有规则都通过。

继续执行沿用原批次；字段核对保存追加字段版本，不会仅因此作废整个批次。材料换版或全部重新执行会使旧执行退出当前位，保留旧记录和失效原因。

中断后能否沿用原批次，取决于任务状态和已提交结果。符合条件时只补跑未完成项及受影响的下游；缺材料或配置不全时先处理原因。字段核对是正常等待：可以补跑失败字段，也可以确认现有值和缺项后进入下游。详见[恢复与继续执行](规则库与审核执行契约.md#恢复与继续执行)。

模型渠道故障会停止后续模型请求，已形成的结果照常保存，批次以 `AUDIT_LLM_CHANNEL_UNAVAILABLE` 结束，等待用户继续。请求结果未知时不自动重发。

审核图只保留当次运行的内存状态，不使用持久化 checkpoint。除了字段核对，没有其他人工等待点。任务“执行结束”不等于检查通过。

审核任务页面的下载范围见[执行契约](规则库与审核执行契约.md#限制)。规则库编制的 Excel 导出、报告模板的原件预览属于各自模块。
