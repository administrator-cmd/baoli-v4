# 业务逻辑

系统将业务维护的 Excel 规则库转为场景配置，对真实材料逐条审核，并保留结论、实际比较过程和原文证据；无法判定时明确说明原因。

## 对象与流程

| 对象 | 含义 |
| --- | --- |
| 场景 | 专家维护的材料、字段、规则、节点、风险和报告配置 |
| 场景版本 | 管理员确认发布后生成的不可变配置 |
| 方案 | 业务用户基于某个场景版本作个性化调整，可继续编辑 |
| 任务 | 创建时冻结方案完整执行配置，用于审核一批真实材料 |

管理员创建场景后直接上传该场景的规则库 Excel，无需下载模板或使用固定表名、表头。选择参与解析的工作表后，LLM 读取完整单元格内容及合并区域，结合当前场景的实际节点和能力目录生成材料、字段、规则、计算和报告候选 JSON。工作表不绑定单个节点；字段、规则和计算分别引用实际节点，系统不自动生成节点。

原文已经明确的业务标准由 LLM 解析；确实缺失、有歧义或存在引用问题时提出具体问题。管理员核对候选后写入场景草稿，业务定义集中存入 `config_json`。重新导入会替换材料、字段、业务规则、计算、报告章节和来源工作表清单，保留流程节点、顺序与依赖；写入前核对修订和当前节点引用。

保存只更新草稿；配置完整且管理员显式发布后才生成生效版本。业务用户从生效场景生成方案，按业务需要调整启停与配置后创建任务，上传材料并执行审核。任务冻结自己的配置，新版本不改写已有方案和任务。场景删除实际移除场景身份和草稿，已有方案、任务、导入历史及已发布版本独立保留。

## 审核结论

结论链条为：审核事项、标准、原文、标准化事实、实际比较、结论及原因。原文与标准化值分别保存，证据展示引用原文、来源、字段属性和内容核对结论，不展示页码、坐标或定位状态。OCR 内部仍保留处理所需的数据。人工纠正后保留系统原判断及来源，缺事实、证据、业务口径或执行能力时不默认通过。

本次抽取值、计算结果及规则结果写入任务 CSV；数据库保存任务索引与证据关联。计算方法和业务判断标准来自规则库，由配置的 LLM 使用真实字段值、上游结果和明确常量执行；程序负责引用、配置结构、数值格式等核对，不提供旧四则计算引擎兜底。RAG 用于查找候选原文和证据。印章主体相似度只用于候选排序，主体是否一致由工作人员确认。

系统不再提供固定 Excel 模板或按模板列转换的路径，节点能力单独配置；场景版本导出完整业务 JSON，停用来源统一交给模型增量解析。静态实现不代表真实规则库导入与审核已经验收，验证范围见[状态台账](当前状态与问题台账.md)。
