# baoli-v4 合同审核验证版

## 本地配置

后端只读取项目根目录的 `.env`。配置优先级为进程环境变量、该 `.env`、代码中的非敏感默认值。`backend` 目录或项目根目录启动后端时读取的是同一份文件；修改 `.env` 后必须重启后端。

以 `.env.example` 为说明创建本地 `.env`。真实 `.env` 已被 `.gitignore` 排除，不应提交。最低必须填写 `BAOLI_DATABASE_URL`，且数据库名必须精确为 `baoli_v4`。`BAOLI_DATA_DIR=data` 会写入项目根目录下的 `data/`；相对路径不依赖启动目录。

数据库密码中如含 `@`、`:`、`/`、`?`、`#` 或 `%`，需要按 SQLAlchemy URL 规则进行百分号编码。Windows 路径可以使用正斜杠，例如 `D:/baoli-v4-data`；也可使用相对的 `data`。数据库初始化由人工执行，应用启动不会建库或执行任何 DDL：

- 执行 `backend/database/schema.sql`：一次即可得到完整结构，并把全部迁移版本写入 `schema_migration`。

**本仓库只保留这一份结构脚本**，不再维护增量脚本。需要改结构时直接改 `schema.sql`，
并在同一文件第 9 节的 `schema_migration` INSERT 里补上对应记录——两处必须同时改，
否则应用启动时的只读校验会因为迁移记录与代码要求不一致而拒绝启动。

`schema.sql` 使用 `CREATE TABLE IF NOT EXISTS`，**不会**给已存在的表补列、改约束或加索引，
因此结构变更后必须**从空库重建**，不能在旧库上重复执行。

应用启动时会**只读校验**结构：缺表、缺列、缺唯一键/外键/触发器或迁移记录不完整都会拒绝启动并指出具体对象，不会自动修表。

需要反复重跑流程时，可以用 `python script/reset_database.py` 清空 `baoli_v4` 库（默认只列出将要删除的表，加 `--yes` 才真正删除），删完后重新执行 `backend/database/schema.sql`。

## 上传体量上限

规则库与业务材料的体量上限是两个**互相独立**的配置，不能共用一个值：规则库是 Excel
配置表，业务材料是合同、协议这类扫描件。

- `BAOLI_MAX_RULEBOOK_BYTES`（默认 31457280 = 30 MiB）
- `BAOLI_MAX_DOCUMENT_BYTES`（默认 134217728 = 128 MiB）

两者都只校验为正数，没有写死的上界；真实运行环境里几十 MiB 的扫描件是正常的。
后端通过只读接口 `GET /api/system/upload-policy` 提供大小上限与允许扩展名；前端入口应读取该接口，
不在页面里另抄一份常量。当前各入口接入状态见 `docs/当前状态与问题台账.md`。实际写入时的最终校验仍在服务端，
超限显式返回 `FILE_TOO_LARGE`。

以上只约束**本系统的上传入口**。8018、8010、OCR 与部署入口（反向代理等）各自的
体量上限是独立的外部契约，本系统不声明、也未经连通验证；超出时会在对应环节返回明确错误。

## 节点版规则库与印章主体检索

> 2026-09-15 收窄：RAG 只做**印章主体检索**。不实现合同全文向量检索、条款 RAG、
> 通用问答，也不做 LLM 主体裁决。现有 OCR、字段抽取与非 RAG 的 LLM 校验继续承担原职责。

规则库支持节点版格式 `contract_review_v3`：七张表分别是 `01_材料检查`、`02_文件处理`、
`03_字段抽取`、`04_文件内部校验`、`05_文件交叉校验`、`06_风险评定`、`07_报告输出`。
它的表头、编号、字段/材料/风险引用、多项清单、加总式与显式参数全部由代码确定性解析，
不调用大模型、不使用向量相似度。

- 旧格式 `contract_review_v1`/`v2` 继续按各自 profile 读取，历史场景、方案、任务与报告不被重新解释。
- 检查等级与风险等级按标签对应读取（Excel 里的「一级风险」等同「一级」）；
  旧格式的「高/中/低/待确认」与节点版的「最高/一级/二级/三级」都原样保留、都能发布。
  PM 原「高/低」与四级标签之间的**对应关系**没有已确认的业务映射，系统不代填，
  会记为需要回答的待确认事项；两套标签各自排序，不相互映射。
- 数值与日期比较都支持非负「允许差值」：相等为 `|左−右| ≤ 差值`，不大于/不晚于为
  `左−右 ≤ 差值`，不小于/不早于为 `右−左 ≤ 差值`；日期差值为天，0 是有效配置。
  差值以 Decimal 传递与计算，不经过浮点，保留精度。
- 每条检查的结果都带上可核对的审核内容：审核标准（取自配置的审核要求原文，未填写时
  明确说明缺什么）、实际使用的输入（**原文值与标准化值分开**保存）、实际比较过程
  （左侧/右侧取值与算式、允许差值、实际差额、加总式的各加数）。结论为异常时算式措辞
  与结论一致，写明超出允许差值，不做成看起来满足条件的写法。
- 材料位的类型结论只有**人工已确认与材料位不符**才阻断依赖它的检查。自动识别给出的
  类型结论仅供参考：类型待复核不改变普通审核（金额、日期、字段比较、条款判断），
  真实原文照常参与判定，类型本身作为一条独立的待确认事项暴露，也不打断正在排队的人工复核。
- 多字段加总只解析「字段 + 字段 + …」，用 Decimal 计算，不使用 eval、Excel 公式或大模型算术；
  未知值不当作零，也不默认人民币、元、5% 或任何单位换算。
- 文件检查中**有真实输入**的三项按实际数据判定：文件格式（声明后缀与声明内容类型）、
  文件大小（真实字节数，MB=1,000,000 字节、MiB=1,048,576 字节）、文件内容（同任务内内容哈希是否重复）。
  格式项按**客户端声明的后缀与内容类型**判定，系统不读取文件字节做类型鉴定：声明明确冲突时
  判不合格，缺失或通用 MIME 时如实说明“按声明后缀判定、未经内容鉴定”，不把它称为真实文件内容鉴定。
  重复项按上传 ID 排除自身，只比对同任务内其他材料位的当前上传。
  清晰度方差、页码连续、有效签章与骑缝章完整性缺少已确认判定依据，运行时明确「不可判定」，不默认通过。
- 证据的「内容依据」与「位置」是两个分开的结论：内容依据回答引文能否在其所属处理产物里
  找到原文（找不到才是真的缺依据）；页码、坐标只回答能否精确定位到页内位置。
  位置缺失或对不上**不影响字段内容与规则判定**，报告与页面把它标为辅助信息。
  骑缝章、签章位置这类确实依赖版面的检查仍按各自的业务判据处理，这条不扩展到普通审核。
- 大小写金额一致性在换算口径确认前明确「不可判定」，不按字符串比较，也不默认通过。
- 风险成立条件按配置组合来源结果：任一模式下有确定不合格即成立、无不合格但有无法判断则无法判断；
  全部模式下必须全部来源适用且确定不合格才成立、存在确定合格则不成立；全部来源不适用则风险不适用。
  缺少来源结果不等于来源合格，但也不会压过已经确定的组合结论。

印章主体检索使用本地 `shibing624/text2vec-base-chinese`：

- `BAOLI_EMBEDDING_MODEL_PATH` 必须指向本机**已经存在**的模型目录；系统不会自动下载权重，
  也不会改用远程模型。未配置或文件不全时，需要主体检索的规则会返回明确错误。
- **索引只对印章识别产物中的主体名称建向量**：页码、坐标、置信度、条目序号与印章类型不进入
  向量文本；识别出的不同主体都作为候选，不自动合并。
- 检索先按当前任务、材料范围、当前上传版本、**产物内容哈希**、索引版本与当前模型过滤候选，
  再做向量排序。产物重新识别后内容哈希变化，旧索引不再适用。相似度只用于排序，
  不构成主体一致的结论。
- 主体核对以规则指定的待核对主体当前有效值查询。**该规则自身**触发印章索引依赖：
  不需要额外启用条款规则，也不需要额外启用文件检查才取得印章产物。
  待核对主体按字段的「产物来源」声明确定（非印章识别那一侧），规则无法确定时明确报错，
  不用印章字段去检索印章自身。
- 结论由工作人员在「取证检索」页选择一致 / 不一致 / 证据不足后保存，与候选和相似度分开记录；
  没有候选时按「未识别主体 / 未建索引 / 索引失效 / 模型失败」分别说明，一律不判通过。
  候选身份由索引号、分块号与产物条目序号三者共同确定，人工复核快照保留完整候选与双方原文。
- 待确认事项（含未填写的成立条件、缺少的单位币种、待确认的配置行）在发布检查中按未处理问题阻断，
  解决前不能发布为可执行版本；系统不删除问题、不代填默认值，也不自动停用绕过。

## 外部服务

大模型执行规则转换、字段抽取和智能校验时需要同时填写：

- `BAOLI_LLM_BASEURL`
- `BAOLI_LLM_APIKEY`
- `BAOLI_LLM_MODEL_NAME`

地址可填写 API 基础地址或完整的 `/chat/completions` 地址；后端只会在地址未以该路径结尾时追加一次，不会臆造 `/v1`。

执行文件处理节点需要：

- `BAOLI_SERVICE_8018_URL`：基础地址，后端调用 `/supported-types` 和 `/validate`。
- `BAOLI_SERVICE_8010_URL`：基础地址，后端调用 `/process`，并将下载到的处理产物保存到本地。
- `BAOLI_SEAL_SERVICE_URL`：基础地址，后端调用 `/predict`。
- `BAOLI_OCR_SERVICE_URL`、`BAOLI_OCR_TOKEN`、`BAOLI_OCR_MODEL`：OCR 完整提交接口、令牌和模型，三者缺一不可。OCR 仅提交当前上传对应的 8010 本地产物，并使用 `BAOLI_OCR_POLL_INTERVAL_SECONDS` 和 `BAOLI_OCR_MAX_WAIT_SECONDS` 控制轮询与总等待预算。提交后会先保存同一作业的 `jobId`；提交结果未知时系统会明确阻止自动重发，需人工核对供应商作业。

`BAOLI_REQUEST_TIMEOUT_SECONDS` 是单次 HTTP 请求超时；OCR 的提交、轮询和下载还有独立的总等待预算。已超过该预算的既有 OCR 作业不会被自动重提，需人工核对或明确重新上传材料。所有外部服务均可暂不配置以查看任务和系统状态；真正执行依赖该服务的操作会返回明确错误。

“已配置，未验证”只表示必需配置项已经填写，未表示数据库或供应商服务已经连通。系统状态接口不会返回密钥、令牌、完整数据库连接串或供应商地址。

本地嵌入模型（`BAOLI_EMBEDDING_MODEL_PATH`）已指向本机 HuggingFace 缓存中实际含
`config.json` / `tokenizer_config.json` / `vocab.txt` / `model.safetensors` 的 snapshot 目录，
系统状态返回 `CONFIGURED_UNVERIFIED`：文件齐备且路径存在，但**未加载推理**，
不能据此认为模型可用或检索质量达标。

## 启动命令

本项目优先使用本机已有 Conda `dd` 环境。以下命令仅供人工执行，本轮未执行：

```powershell
conda activate dd
cd backend
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

另开一个终端：

```powershell
cd frontend
npm run dev
```

前端默认使用 `/api`，开发代理固定指向 `http://127.0.0.1:8000`；后端 CORS 允许 `http://localhost:5173` 与 `http://127.0.0.1:5173`。

## 功能模块（六组菜单）

- **场景管理**：场景列表、材料配置、字段配置、规则配置、规则库导入。场景身份维护名称/业务类型/启停/逻辑删除；材料、字段、规则与报告配置只有一份、保存即生效（来源可为页面编辑或 Excel 导入）。配置不完整时保存仍然成功，但页面明确标为“尚未生效”并给出具体原因，已发布版本保持为上一个可用版本。
- **方案管理**：方案列表、方案版本。方案是对该场景的可复用规则选择；草稿保存显式选择，发布冻结当时的场景配置、显式规则与自动依赖；已发布方案版本不可覆盖，场景之后修改不影响它。
- **审核管理**：审核任务、人工复核、执行记录。新任务只能从“已发布且启用的方案版本”创建并保存执行快照；旧任务没有方案关联时显示“历史任务配置”，不会被迁移或改写。
- **资料管理**：审核材料、证据记录。上传、替换、移除当前文件都会产生输入修订并使依赖结果失效；历史文件保留可下载。
- **报告管理**：审核报告、风险结果。报告由真实报告节点生成（三个信号分别展示），备注可编辑、正文不可手改；风险只统计当前有效执行批次，命中只计异常。
- **系统管理**：服务状态、操作日志。“已配置，未验证”不表示服务就绪；操作日志记录真实发生的写操作与后台命令。

旧链接 `/imports?job=…` 与 `/audits?task=…` 会显式重定向到新的导入/任务页面（保留对象）；默认首页为审核任务列表。

未执行数据库脚本、服务启动、浏览器、本地嵌入模型推理或外部文档服务验证。
节点版 Excel 适配、审核任务 RAG 与草稿保真改造只完成代码与迁移脚本的静态实现，未运行验证。
场景配置改为“保存即生效”后，真实数据库上的空库重建、保存链路与任务快照不受影响的验证已执行；
规则库导入、外部服务与前端页面仍未验证。

审核闭环与定位解除阻断（2026-09-17 第二轮）同样只完成静态实现与真实记录的**只读复算**：
算子输出对比过程、原文/标准化值分流、材料类型待复核不再阻断、字段“证据不足”后触发下游重算、
内容依据与位置分开呈现，均在现有真实任务记录上静态核对过，但**没有运行过审核任务**，
新增的对比过程与待确认事项在实际页面与报告中的呈现仍未运行验证。

**能力目录与发布前能力校验（2026-09-18 第二轮）也是静态实现**：新增
`backend/app/domain/capabilities.py` 作为后端能力的单一事实来源（22 项能力），
节点约束、中文标签、取证/判定路由、页面检查方式下拉与状态口径都从它派生；
规则引用的能力不在目录中时导入与发布明确失败；能力未实现时发布检查默认阻断，
必须逐条确认（`acknowledged_capability_gaps`）后才放行，运行期明确返回「不可判定」。
本轮只做了本地模块导入与纯函数核对；**发布接口的真实请求、页面渲染、审核任务执行、
旧任务与旧版本兼容性均未运行验证**。能力目录描述的是当前实现，不等于系统支持任意业务场景。

**数据库结构**：`schema.sql` 是唯一的结构脚本。当前库必须由它建立过
（含 `scenario_draft_section.report_code`、`scenario_draft_field.artifact_source`、
`scenario_draft.profile_version`、`scenario_draft.sync_error`、三张草稿表的 `source_ref`、
`import_job` 的 `(created_at, id)` 索引等），否则应用启动时的只读结构校验会拒绝启动，
这是预期行为，不是配置错误。`schema.sql` 不会给已存在的表补列，
结构变更后必须从空库重建。

LangGraph 使用社区 MySQL saver（`langgraph-checkpoint-mysql`），checkpoint 保存在同一个 `baoli_v4` 库。应用启动不会建表，也不会调用 `saver.setup()`；缺表或缺依赖时启动会给出明确错误，不会回退到内存 saver。启动检查会核对 `checkpoints`、`checkpoint_blobs`、`checkpoint_writes`、`checkpoint_migrations` 四张表以及已应用的迁移版本是否覆盖依赖包要求；依赖升级后若库结构没跟上，启动会明确报 `CHECKPOINT_MIGRATIONS_OUTDATED`。该兼容性尚未在本机运行验证。

checkpoint 存储的连接配置（含 `autocommit`）由该依赖包自身的事务契约决定，应用不修改它；应用负责的是业务事务与图 checkpoint 两套提交之间的对账。

每个材料位只有一个当前文件；再次上传是替换版本，不是追加第二份同类材料。**首次补传可选材料同样属于输入变化**：如果任务已经越过了材料检查，补传会失效相关产物、待办与执行结果并让流程回到材料检查重新计算。本轮仍不支持多发票求和、多合同自动分组等汇总取数。
